# 标书撰写

除了要先完成项目建档，没有其他前置条件：目录、spec、任务清单都不是必须的。只写用户要求的范围，不补造投标人事实。

## 1. 确定本次工作

- 读取项目 `AGENTS.md`；没有就用 `bid-project-setup`。生成章节、进度清单或报告不触发重新建档；招标来源或已确认材料发生实质变化的，按建档规则更新。
- 读取档案中的 **技术文件编制方式**（明标 / 暗标 / 未明示按明标）与 **本项目公开资料路径**；缺字段时按建档规则补记。明暗标判定见建档/检查「勾选态判定阶梯」：ActiveX/内容控件优先，模板条件句不得压过未勾选。
- 定位招标文件、有效澄清、事实材料、范围和输出目录。可选的 `标书目录.md`、`工程量清单.md`、`标书初稿讨论.md`、`写作任务清单.md` 只复用当前有效版本；失效或与招标冲突的，处理受影响部分，不按旧结论写作。
- 全套按已有有效目录或招标规定的格式写；局部按用户指定的章节、评分点或任务编号定位。对应关系不止一个时才询问；不为一次性的局部写作创建任务清单，也不强制为直接局部写作新建目录基线。
- **蓝图**：若 `标书初稿讨论.md` 中本次范围存在「章节蓝图」且状态为已确认，则按蓝图三级标题扩写，不擅自增删/重排小节；要改结构先回 `bid-spec` 更新蓝图。蓝图为草案或缺失时，用户未要求先定蓝图的可直接写；用户要求按蓝图写而蓝图未确认的，先走 `bid-spec`（硬闸门）。用户已明确「跳过蓝图直接写」的，按 spec 登记执行。
- 执行任务时核对真实依赖，开始后把任务标为“进行中”。只缺事实材料的用【待补】继续；缺会改变写法的决定，就暂停相关章节，先写其他不受影响的章节。

## 2. 按章起草与保存

章节文件固定放在 `投标输出/<项目名>/正文/`，一个可独立交付的章节存一个文件，文件名用编号加章节名；表格内的条目和小标题不各自建文件。固定格式、措辞和签章占位遵循招标原文。方案要落实得分条件和技术/服务要求；证据可以放进附件并在正文建立引用；正文不写内部分值、REQ/BOQ ID 或风险话术。

每章只读取相关原文、当前有效决策和材料；跨章节的人员、日期、设备等信息从已有文件与 `投标输出/<项目名>/关键参数台簿.md`（若有）里查，不凭对话记忆。不得擅自新增用户范围之外的承诺、参数、业绩、金额和交期。缺事实写【待补】，其他成员接口写【待补·其他成员】。有有效基线时，数量、规格及计数口径从同一 REQ/BOQ 基线取得；派生数量与合计用计算工具复核，不凭正文记忆改写。项目事实与参数优先用档案中的公开资料路径；无材料则【待补】，不编造。

**写作规格**：起草前读取 [写作质量规格](references/writing-quality.md)，按章类型套用全量或轻量规则。写完一章、更新进度并向用户确认前，先完成该文件中的「章末优档自检」（软闸门）；未过先回修。

**明暗标**：

- 明标或未明示按明标：允许本单位正当表述；禁止把竞争者/他单位名称当作己方能力背书写入正文，命中则删除或改写，拿不准标【待核·身份】。
- 暗标（仅适用于招标要求暗标的范围，通常技术标分册；招标原文未按分册区分时适用全部技术文件；商务/资格分册不受此限）：正文与图表不得出现本单位名、Logo、业绩、人员姓名与证书、自指（我院/我公司等）；缺专用脱敏词表时，对可疑词标【待核·身份】，不静默当作已合规。

创建或更新进度清单 `投标输出/<项目名>/撰写进度.md`（不要用普通 `README.md` 当进度清单），保留其他章节的记录：
- 本次范围（全套/局部）、纳入的章节与剩余范围；全套时列明全部计划章节；
- 本次招标、澄清及可选产物的路径、版本/日期、大小和修改时间；技术文件编制方式；
- 章节文件相对路径（相对 `正文/`）、响应的 REQ/BOQ ID（有基线时）、依据条款/决策编号、状态（未开始/进行中/草稿完成/阻塞）及下一步；
- **中文字数**：实际中文字符数；有蓝图或大纲建议篇幅时同时登记建议中文字数（口径见 writing-quality）；
- **评分点响应表**：已附 / 不适用（原因）/ 待补；
- **参数台簿**：本章是否已同步 `关键参数台簿.md`；
- 全部待补及其所在文件位置；
- 授权整改时：已处理的问题编号（`P-xxx`）→ 改动文件/位置（供检查整改复核使用）。

每写完一章（或未完成章节的一个可续写段落）就保存。换对话续写时，先核对来源是否有变化，再读进度清单、目标章节和相关依据继续；不得覆盖已完成的正文去重新生成全套。

## 3. 交付与检查

交付前确认：本次文件都存在、进度清单与文件一致、待补全部登记；有任务清单时同步任务状态；优档自检已做过或已注明本章仅轻量规则。"草稿完成/任务已完成"允许有已登记的待补，不代表可以递交。

局部完成就直接交付本次成果和剩余范围。只有全套草稿完成、或覆盖全套的任务清单全部完成时，才自动调用 `bid-review`；局部任务清单全部完成不等于全套完成。用户要求阶段性检查时也可调用。

撰写后调用检查前，由**主上下文**（撰写方）一次问清并记下：
1. 检查模式：初步 / 标准 / 完整；
2. 是否附模拟评分（需要 / 不需要）。

用户已明确指定的不重复问。将选择与其他交接一并传给检查子代理，**不要**把「模式未定、由检查方询问」留给独立子代理——子代理通常无法直接问用户。

调用检查时，必须新建一个不继承撰写对话的独立检查子代理；即使撰写者本身也是子代理，也不能用它自查代替。只交付检查技能路径、项目档案、完整招标与澄清、当前投标文件及附件（以 `撰写进度.md` 中的文件集为候选）、事实材料、可选 spec、参数台簿（若有）、各输入版本、输出目录、**已选定的模式与是否模拟评分**、明确纳入/排除的范围；不传撰写过程或自评结论。无法创建独立检查子代理时，交付初稿并明确标注"未完成独立检查"，不能降级为撰写者自查。

拿到检查报告后，向用户交付问题摘要，不自动整改；用户明确要求整改的，按授权范围处理，并在 `撰写进度.md` 记录「已处理 `P-xxx` → 改动文件/位置」，整改复核时把该记录交给检查。无法检查时说明未完成原因，不要把交接性核对当作合规检查。
