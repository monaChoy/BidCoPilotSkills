# 解析覆盖与判断边界

## 通用登记

每个输入记录路径、扩展名、检测格式、大小、UTC mtime 和 SHA-256。格式识别结合文件头与扩展名；其他格式至少保留文件指纹。`legacy-ole-container` 表示 OLE 复合容器，内部结构未解析。

单文件失败不掩盖其他文件。`parsed` 是相应解析器完成，`partial` 是部分工具失败，`unsupported` 是仅登记指纹或格式未支持，`error` 是解析失败。退出码只反映提取完整性，不是风险判定。

## DOCX / OOXML

使用 Python 标准库 ZIP 与 XML 解析：

- `docProps/core.xml`、`app.xml`、`custom.xml` 的非空属性；摘要重点保留作者、保存人、单位、模板、时间和标题等字段。
- 正文及页眉页脚、批注、脚注、尾注和设置部件中的修订元素、直接隐藏格式运行、批注和 RSID。
- 页眉页脚文字、外部关系、customXml、嵌入对象、媒体对象和宏部件；嵌入对象及媒体记录字节数与 SHA-256。

正文普通文字不进入 summary。直接 `vanish/webHidden` 可定位到运行，但样式继承形成的隐藏文字未完整展开；OLE 对象内部、宏内容和正文语义查重未覆盖。RSID 是编辑会话相关标识，可继承或变化，不是人员、电脑或单位的身份证明。

## PDF

使用已有 Poppler：

- `pdfinfo -rawdates`：常规 Info、创建工具、日期、页数、加密和表单等。
- `pdfinfo -custom -rawdates`：补充标准及自定义 Info；该命令不返回常规页数等字段。
- `pdfinfo -meta`：XMP 元数据。
- `pdfinfo -js`：工具可取得的 JavaScript。
- `pdfdetach -list`：嵌入附件清单。

manifest 保存命令、返回码和输出，summary 只保留关键字段及大小/数量。完整增量修订历史、对象级来源鉴定、可选内容组和批注外观逐项审计未覆盖；没有这些结果不能反推历史不存在。加密或损坏文件按实际命令结果记失败，不尝试绕过密码。

## XML / 造价 XML

使用 Python 标准库 XML 解析器，记录根元素和元素数；从元素名、属性名、常见命名字段及短“字段：值”文本中筛选作者、编制人、单位、软件、序列号、加密锁和机器码等候选。每项保留 XML 路径、键、原值和来源类型。

`.xml` 文件直接进入解析器，由 XML 声明和 BOM 识别编码；覆盖 UTF-8 及带 BOM 的 UTF-16 LE/BE。空文件、损坏或非 XML 内容记 `error`，与仅登记指纹的 `unsupported` 分开。

普通工程量清单不进入 summary。超过 100 条命中时 summary 截断并标记，须按任务回查 manifest。字段名命中不证明字段语义，原值也不经外部真实性验证；旧版 Office/WPS 和专有计价二进制文件不在 XML 解析范围内。

## 多文件确定性比较

- **文件哈希组**：相同 SHA-256 表示文件字节相同。
- **嵌入对象组**：当前覆盖 DOCX 媒体与嵌入部件；相同哈希表示对应部件字节相同，不说明可见内容必然相同。
- **字段组**：同一规范化字段名和值出现在不同输入时保留全部位置。空白和超过 500 字符的值不参与字段比较。

summary 每类最多保留 50 组并标记截断。上述比较不覆盖正文相似度、图像视觉相似度、报价规律或不同格式转换后的内容等价；相同事实需结合模板、转换和合法共用材料等成因人工解释。
