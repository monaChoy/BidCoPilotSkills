# 标书目录整理

产出 `投标输出/<项目名>/工程量清单.md` 和 `标书目录.md`。投标文件格式规定骨架，全量招标要求决定结构覆盖；评分只是其中一类，不计分或不在清单中的义务也须安排落点。

## 1. 定位输入与复用基线

读取项目 `AGENTS.md`；缺少时使用 `bid-project-setup`。定位完整招标文件及有效澄清、相关参考材料、已有人工目录和输出路径，复用档案中的内容角色、重复关系和主读取文件约定。角色仍不明时查看首页、目录和内容，不按文件名猜测；扫描件分段视觉识读，关键数字、错位及歧义回看原始版式。

两个产物头部均记录当前版本、状态、范围、来源路径及版本/日期、文件大小和修改时间、用户确认情况。建立基线、判定同名替换或声称内容相同时记录并核对 SHA-256；后续复用比较来源版本及已记录哈希。

输入未变且已有有效清单时，目录调整复用基线，不重新逐行提取。只有用户要求重提清单、来源变化或没有有效基线时才完整提取；来源局部变化只重核受影响分组、关联要求及汇总。同名来源改变不能仅凭名称复用。

## 2. 建立来源覆盖与全量要求索引

先在 `标书目录.md` 建立来源覆盖表，覆盖公告、须知/前附表、前附件、评标办法、投标文件格式、合同、技术规范、工程量清单、图纸/引用附件、补充修改及有效澄清。每个实际存在的区域记录位置、批次和状态：已查/未查/待核/不适用/范围外。已查记录覆盖位置，未查/待核记录下一处位置及原因，不适用/范围外记录依据。项目没有的卷册记不适用，用户排除的内容记本次范围外，二者不冒充已查。

按来源区域分批提取要求，完成一批即保存索引和下一处位置。要求分类复用 `bid-review` 的清单、门槛、独立技术与服务义务、报价、联合体及 `bid-scoring` 的评分定义；固定格式、必备附件和递交要求归入门槛，交付验收、BIM、接口、培训运维等未被清单或评分覆盖的内容归入独立技术与服务义务。参考材料只提供线索，不增加招标义务。

全量要求索引使用：

`要求ID｜类别｜摘要｜强制/条件/示例｜来源｜目录落点｜关联清单/附件｜状态`

- 要求使用 `REQ-001` 起的稳定 ID，清单行使用 `BOQ-001` 起的稳定 ID。更新保留未变项 ID，新增项使用未占用编号；失效项在变更记录保留替代或失效关系，不回收编号。
- 同一要求多处出现时关联来源，不重复建项。保留适用条件及精确值、上下限、区间等关系；示例只关联其说明的要求，不提升为强制承诺。
- 落点可以是章节、固定表格、附件、人工递交事项，或有依据的“不单独设章”。每个 REQ 均须有落点或具体待核原因；条件是否适用不明时标待核并写明影响范围。
- 清单行同时进入要求索引的关联字段，不重复抄写长参数。要求索引、来源覆盖和清单共同构成后续设计、撰写与检查的基线。

## 3. 提取与回查清单

- 按原顺序从正式工程量清单提取；缺少时寻找设备、供货或服务等功能等价清册，候选有歧义则询问。用户确认确无清单时，记录确认和替代依据，按招标范围继续，不虚构条目总数。
- 每行保留 BOQ ID、原编号、分类路径、名称、区分同名项的特征摘要、单位、数量、周期（适用时）、来源和核对状态。不得从已有目录、参考资料或投标文件反推。
- 合并跨页续行，表头及参数续文不另计行；同名不同位置、规格或服务边界不得合并。品牌选用表若是已有条目的约束，关联该行而非再计一次；不填写投标人自选品牌或报价。
- 第二遍从原文逐组回查编号、分组起止、跨页衔接、名称及关键字段，不能只比总数。修正已查明问题；识读不清保留待核及具体位置。
- 分批保存已核行、待核行、来源覆盖及下一处位置；换对话从文件恢复，不重复全量抽取。派生数量或合计使用计算工具复核，保持清单行、分类父项和技术分点的计数口径分离。

清单只有来源分组覆盖完整、无缺失重复且各行已回查后才标“已核对”。无清单分支标“不适用”，注明用户确认和已核替代范围；待核项列明受影响目录位置。

## 4. 建立目录与映射

- 按招标“投标文件格式”建立规定章节、表格和附件骨架，不改动强制顺序或固定表单。互斥表单可归入逻辑父章，但保留原表单及适用条件。
- 有人工目录时以其为底稿，只为强制要求和覆盖缺口调整；无格式章节时按评标办法和响应内容组织，并注明自建结构。表内证明材料按原文展开或建资料索引，不凭经验添加附件。
- 将标题树草稿、评分类 REQ、来源版本及本次范围交给 `bid-scoring`，执行评分基准提取和结构核对；把返回的评分条件、主落点、关联证据位置和核对结果保存到目录，不另建评分报告，不触发模拟评分。
- 清单行映射到语义最近的技术章节或响应表，允许多行共用一个章节；同一响应目的不重复展开整棵清单树。商务报价与技术内容分开保留。
- 标题细分到可指导写作即止，不复制清单数量、长参数或证据字段到标题；门槛、独立义务和固定附件可落在表格或人工核对清单，不机械增设标题。

在 `工程量清单.md` 每行增加“技术落点”列；在 `标书目录.md` 保存标题树、来源覆盖表、全量要求索引、评分点索引、门槛及固定附件/递交落点、疑问和变更记录。多个位置共同支持同一要求时保留关联，不强求证据只出现一次。

## 5. 闭合、确认与更新

先保存可审阅草稿，集中展示实质调整、待核事项和需要决定的问题；已确认且未变化的事项不重问。交付前用工具核对：

- 每个来源区域均有状态，范围内无未查区域；每个 REQ 均有有效落点或具体待核原因，每个 BOQ 的技术落点存在于标题树或响应表。
- 评分按不重叠层级加总，清单按稳定行 ID 去重，分类父项、技术分点和要求项不混入清单行数；数量、合计及版本/哈希核对有计算或工具记录。

“结构覆盖完成”只表示本次范围内来源已查且标题、表格、附件或人工事项均有安排，不表示正文满足。只有全部来源均已查或不适用且全量要求闭合时，才声称“全文要求整理完成”；存在范围外区域时只声明本次范围结果。

本次范围内规定格式、评分、门槛、清单、独立技术/服务义务、交付验收、固定附件及递交要求全部闭合，清单已核对或替代依据已确认，并经用户确认后才标“已冻结”。待核或受影响目录未确定时标“草稿/未冻结”，可继续设计不受影响章节，但不冻结整体。

冻结后变更先形成新版本草稿，保留旧版；确认后明确替代关系并维护当前有效版本。历史文件不得与当前版本并列使用。目录只声明结构覆盖，“正文覆盖完成”由 `bid-review` 依据实质正文、表格和附件证据判断。需要内容策略时继续 `bid-spec`，也可直接进入撰写。
