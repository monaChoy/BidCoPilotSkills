# 标书目录整理

> **没有正式工程量清单也可以整理目录**：勘察设计、咨询、监理、检测等项目，先查招标原文中的设备/供货/服务等功能等价清册；确无清册时，经用户确认后按招标范围、服务任务、成果交付要求、投标文件格式和评分办法组织章节及来源索引，清单标为“不适用”。不得把分散的技术义务虚构成工程量清单，也不得从已有目录、参考资料反推条目和总数。无清单不等于无报价或工作量要求，仍以招标原文为准。

产出 `投标输出/<项目名>/工程量清单.md` 和 `标书目录.md`。招标文件里的“投标文件格式”决定目录骨架，全量招标要求决定结构覆盖；评分只是其中一类，不计分或不在清单中的义务也须安排落点。每个清单行都要能追溯到技术响应位置，但不要求一行一个标题。

## 1. 定位输入与复用基线

读取项目 `AGENTS.md`；没有就先用 `bid-project-setup` 建档。定位完整招标文件及有效澄清、相关参考材料、已有的人工目录和输出路径，复用档案中的内容角色、重复关系和正文读取文件约定。角色仍不明时查看首页、目录和内容，不按文件名猜测；扫描件分段看图辨认，遇到关键数字、转换错位或歧义时回看原始版式，确实无法确认的保留来源信息并记“待核”。

两个产物头部都要记录：当前版本、状态、范围、来源路径及版本/日期、文件大小和修改时间、用户确认情况。建立基线、判定同名替换或声称内容相同时记录并核对 SHA-256；后续复用比较来源版本及已记录哈希。来源文件同名但内容变了的，不能仅凭文件名复用旧结论；更新时核对受影响的内容。

输入未变且已有有效清单时，目录调整复用基线，不重新逐行提取。只有用户要求重提清单、来源变化或没有有效基线时才完整提取；来源局部变化只重核受影响分组、关联要求及汇总。同名来源改变不能仅凭名称复用。

## 2. 建立来源覆盖与全量要求索引

先在 `标书目录.md` 建立来源覆盖表，覆盖公告、须知/前附表、前附件、评标办法、投标文件格式、合同、技术规范、工程量清单、图纸/引用附件、补充修改及有效澄清。每个实际存在的区域记录位置、批次和状态：已查/未查/待核/不适用/范围外。已查记录覆盖位置，未查/待核记录下一处位置及原因，不适用/范围外记录依据。项目没有的卷册记不适用，用户排除的内容记本次范围外，二者不冒充已查。

按来源区域分批提取要求，完成一批即保存索引和下一处位置。要求分类复用 `bid-review` 的清单、门槛、独立技术与服务义务、报价、联合体及 `bid-scoring` 的评分定义；固定格式、必备附件和递交要求归入门槛，交付验收、BIM、接口、培训运维等未被清单或评分覆盖的内容归入独立技术与服务义务。参考材料只提供线索，不增加招标义务。

全量要求索引使用：

`要求ID｜类别｜摘要｜强制/条件/示例｜来源｜目录落点｜关联清单/附件｜状态`

- 要求使用 `REQ-001` 起的稳定 ID，清单行使用 `BOQ-001` 起的稳定 ID。更新保留未变项 ID，新增项使用未占用编号；失效项在变更记录保留替代或失效关系，不回收编号。
- 同一要求多处出现时关联来源，不重复建项。保留适用条件及精确值、上下限、区间等关系；示例只关联其说明的要求，不提升为强制承诺。
- 落点可以是章节、固定表格、附件、人工递交事项，或有依据的“不单独设章”。每个 REQ 均须有落点或具体待核原因；条件是否适用不明时标待核并写明影响范围。
- 清单行同时进入要求索引的关联字段，不重复抄写长参数。要求索引、来源覆盖和清单共同构成后续设计、撰写与检查的基线。

## 3. 提取与回查清单

- 按原顺序从正式的工程量清单提取；没有正式清单时，找设备、供货或服务等作用等价的清册，候选有歧义时问用户。用户确认确实没有清单的，记下用户确认和替代依据，按招标范围继续，不要编造条目总数。
- 每行保留 BOQ ID、原编号、分类路径、名称、能区分同名项的特征摘要、单位、数量、周期（适用时）、来源和核对状态。不得从已有目录、参考资料或投标文件反推清单内容。
- 跨页的续行合并到原行，表头和参数续文不另计行；同名但位置、规格或服务边界不同的，不得合并。品牌选用表如果只是对已有条目的选用限制，关联到那一行，不要再计一次；也不要填写投标人自选品牌或报价。
- 第二遍从原文逐组回查编号、分组起止、跨页衔接、名称和关键字段，不能只比对总数。查明的问题直接修正；辨认不清的记“待核”并写明具体位置。
- 分批保存已核行、待核行、来源覆盖情况和下一处位置；换对话续接时从文件恢复，不要重新全量抽取。派生数量或合计使用计算工具复核，保持清单行、分类父项和技术分点的计数口径分离。

清单只有来源分组覆盖完整、无缺失无重复、且各行都已回查，才能标“已核对”。无清单的分支标“不适用”，注明用户确认和已核过的替代范围。待核项要列明影响哪些目录位置。

## 4. 建立目录与映射

- 按招标文件的“投标文件格式”搭建规定章节、表格和附件骨架；不得改动强制顺序或固定表单。互斥的表单可以归入一个逻辑父章，但要保留原表单和各自的适用条件。
- 有人工目录的，以人工目录为底稿，只针对强制要求和覆盖缺口做调整；招标没有规定格式章节的，按评标办法和响应内容自行组织，并注明这是自建结构。
- 表格里要求的证明材料，按原文展开或建资料索引，不要凭通用经验自行添加附件要求。资格和门槛要求也要有响应位置，但不标分值。
- 将标题树草稿、评分类 REQ、来源版本及本次范围交给 `bid-scoring`，执行评分基准提取和结构核对；把返回的评分条件、主响应位置、关联证据位置和核对结果保存到目录，不另建评分报告，不触发模拟评分。
- 清单行映射到意思最接近的技术章节或响应表，允许多行共用一个章节；同一个响应目的，不要重复展开整棵清单树。商务报价和技术内容分开保留。
- 参考材料只能用来启发背景和方案分组，不能增加招标义务。标题细分到能指导写作就停，不要把清单数量、长参数或证据字段搬进标题；门槛、独立义务和固定附件可落在表格或人工核对清单，不机械增设标题。

在 `工程量清单.md` 标明基线类型：正式清单 / 功能等价清册 / 不适用；有清单或清册时每行增加“技术响应位置”列，无清单时只保留确认与替代依据，不生成清单行数。在 `标书目录.md` 保存标题树、来源覆盖表、全量要求索引、评分点索引、门槛及固定附件/递交要求的响应位置、疑问及影响范围和变更记录；无清单时，另将招标范围、服务任务和成果交付要求对应到响应位置及来源。多个位置共同支持同一要求时，把关联都保留，不强求证据只出现一次。

## 5. 闭合、确认与更新

先保存可审阅的草稿，向用户集中展示实质调整、待核事项和需要决定的问题，并给出推荐；已确认且没变化的事项不重复问，也不依赖外部访谈技能。交付前用工具核对：

- 每个来源区域均有状态，范围内无未查区域；每个 REQ 均有有效响应位置或具体待核原因，每个 BOQ 的技术响应位置存在于标题树或响应表。
- 评分按不重叠层级加总，清单按稳定行 ID 去重，分类父项、技术分点和要求项不混入清单行数；数量、合计及版本/哈希核对有计算或工具记录。

“结构覆盖完成”只表示本次范围内来源已查且标题、表格、附件或人工事项均有安排，不表示正文满足。只有全部来源均已查或不适用且全量要求闭合时，才声称“全文要求整理完成”；存在范围外区域时只声明本次范围结果。

本次范围内规定格式、评分、门槛、清单、独立技术/服务义务、交付验收、固定附件及递交要求全部闭合，清单已核对或替代依据已确认，并经用户确认后才标“已冻结”。待核或受影响目录没定下来时标“草稿/未冻结”；不受影响章节的后续设计可以继续，但不得把整体标为冻结。

冻结后要变更的，先形成新版本草稿并保留旧版；用户确认后写清新版本替代哪一版，并把 `标书目录.md` 维护为当前有效版本。历史版本不得与当前版本并列使用；不要只追加一段变更说明，却留着错误的当前标题树。目录只声明结构覆盖，“正文覆盖完成”由 `bid-review` 依据实质正文、表格和附件证据判断。之后需要内容策略就继续 `bid-spec`，也可以直接进入撰写。
