# 标书检查

以招标文件及有效澄清为要求依据。除了要先完成项目建档，没有目录、spec 或撰写方面的前置条件。检查阶段只写本次报告及图片真实性配套报告/证据，不改输入、不自动整改；建档要在检查前完成。

## 1. 确认输入与范围

- 读取项目 `AGENTS.md`；没有就用 `bid-project-setup`。只有招标来源、澄清或已确认材料发生实质变化时才更新档案；新增的生成报告或章节不触发重新建档。本次投标文件集及其变化直接登记在报告里。
- 确定全部招标文件及有效澄清、本次投标文件及附件、相关事实材料、可选 spec 和输出目录。**定位投标文件集时，先读** `投标输出/<项目名>/撰写进度.md`（若存在）作为文件集候选，再与用户本次提供的文件合并；章节默认在 `投标输出/<项目名>/正文/`。标准及完整模式同时确定图片真实性检查范围、可选第三方检查报告和配套产物目录。遵循项目约定的正文读取文件；遇到转换错位、关键数字或歧义时回看原始版式，无法可靠辨认的标为“待人工核实”，不要猜。
- 每个输入都记录路径、文件版本或日期、文件大小和修改时间；同名文件内容变了的，不得仅凭文件名沿用旧结论，有疑问就再比对内容或摘要。澄清要注明修改了哪些条款；效力或冲突无法确定的，列为待核。
- 明确本次是全套还是阶段性范围。阶段性范围要写明纳入的章节、商务/技术侧、排除范围和跨章节依赖；用户没指定且影响判断时，集中询问一次。用户明确接受抽样时，报告显著标为“抽样检查”，抽样结果不得称为标准或完整模式的全套检查。
- 标准及完整模式在范围信息中分别记录检查执行日、投标截止日、投标文件签署日和招标指定的其他有效期基准日；日期从原文或环境取得，签署日不替代投标截止日。另记录预计递交日或临期观察日：招标或用户提供日期/准备窗口时优先采用，未提供时默认取检查执行日后 15 个日历日。临期观察只提示准备风险，不作为合规基准。
- 综合检查的模式与是否模拟评分：**作为子代理收到调用方已选定的模式时直接执行，不重问**；主上下文（用户直接调用）未指定时询问，不代选。未收到模式且当前无法询问用户时，报告「未完成：缺模式」，不代选。模式含义：**初步**只查清单及分点覆盖；**标准**增加门槛、证件与有效期、图片真实性、独立技术/服务义务、报价、评分和一致性核查；**完整**再增加外部引用及适用的证件外部状态核验。初步模式不自动扩大图片检查，用户单独要求图片检查时直接调用 `image-authenticity-review`。用户已明确只查引用或内部矛盾的，按下方「单项检查」执行，不要求补选综合模式。
- 综合检查时同时确认“是否需要附模拟评分（预计得分及依据）？”；调用方或用户已明确选择的复用，不重复询问。把选择记入报告并传给独立检查子代理；未答复时可以先做检查，但不能自行视为同意评分。任何综合模式都可以附评分；初步模式选评分时，只额外增加评分所需的基准提取和正文核对，不自动扩大其他检查范围。单项检查不默认附模拟评分；用户另有明确估分要求时才调用评分分支。
- 用户明确没有招标文件时，仍可按要求检查内部质量与证据，但必须读取 [证据分类与覆盖结案](references/evidence-and-completion.md)，按其中的无招标文件分支限定结论。

所有检查类别都先判断范围：本次未纳入的要求记“本次范围外”，项目本身不适用的要求记“不适用”并附依据；两者都不算缺陷。范围内的要求依赖范围外材料时，只记录证据待核，不要把未审材料判成缺失。

### 单项检查（引用 / 内部矛盾）

- 只核对引文、规范编号/年份、转述是否准确、有没有断章取义时，按单项范围执行：引用核验复用第5节；招标原话对照结合第6节的要求与响应证据。只查人员、工期、指标或数字的前后矛盾时，读取 [标准检查类别](references/check-categories.md) 的「一致性与事实」和「多分册」规则。无需先执行其他类别，不因单项检查重建清单、检查报价或启动全套审查。
- 单项检查仍遵守输入版本、独立性、分批报告和第6节的证据要求。报告记录本次类别、纳入的载体及跨章节依赖，并列明未检查的类别；覆盖进度和结案条件只适用于本次范围。综合完整模式仍保留引用核验，标准模式仍保留一致性检查。单项结果不代表全套已检查。

## 2. 独立检查与报告

先识别是不是中断续查：输入版本、模式或单项类别、纳入/排除范围及独立性都一致时，才复用已有的未完成或部分完成报告；首次检查、上述任一条件变化或整改复核时新建报告，不能把综合检查的进度带进单项报告再按缩小后的范围结案。

用户直接调用检查且主上下文未参与撰写时，主上下文可作为独立主检查员。撰写后调用检查必须新建一个不继承撰写对话的独立检查子代理；撰写者即使本身也是子代理，也不能自查代替。无法创建时报告“未完成独立检查”。大型文档、内容/图片并行、子代理超时和失败接管必须读取 [大型文档并行与续查](references/large-document-review.md)；不得由多个代理同时写主报告。

调用方交付技能路径、输入及版本清单、已选定的模式或单项类别、是否模拟评分、范围和报告路径；标准及完整模式同时交付 `image-authenticity-review` 技能路径、图片范围和配套产物目录，不传撰写过程或自评结论。整改复核时，若存在 `撰写进度.md` 中的「已处理 P-xxx」记录，一并作为改动范围输入。

子代理返回后，调用方交付前须复核报告状态、统计、过期断点及高风险问题，并抽核原始版式中的关键数字、日期和跨栏表格；发现误报或误读时回看证据、原位更正 C/P 状态和计数，保留排除依据。调用方抽核不替代独立检查，也不能只凭子代理摘要验收。

报告路径为 `投标输出/<项目名>/标书检查报告-YYYYMMDD-HHmmss.md`，使用当地时间；重名追加 `-02` 等后缀，不覆盖旧报告。需要新建报告时，开始检查的同时就创建：

- 模拟评分：需要 / 不需要 / 待答复

按招标章节或清单分组、分批处理，每批只读取所需的原文、响应和关联证据；查完一批就保存核对表、问题、分类覆盖和下一处位置。下一处位置只在“检查进度”一节维护，其他小节引用该节；每批同步更新统计，清除过期的断点说明。没有异常的批也要保留一行记录，不要复制整段原文。不要等到全查完才写报告，也不要求一次把全部文档塞进上下文。

核对行使用报告内稳定 `C-001` 起编号，问题使用 `P-001` 起编号，均按实际登记顺序分配，不按批次预留号段；续查及整改复核不重排旧编号。C 是本次核对执行 ID，P 是问题 ID，REQ/BOQ 是跨技能基线 ID，三者不得互相替代。无有效基线时，REQ/BOQ 基线 ID 栏记“待映射”，使用 C、原行标识和来源位置完成本次核对，不另发 REQ/BOQ。问题状态原位更新（待核 / 已确认 / 已排除），保留排除依据。主结论已确认但含未决子项时标“已确认（含子项待核）”并列明子项；主结论依赖未决证据时才标“待核”。已排除项不评严重级别，不计入未排除问题数。主报告的“问题记录”分状态列出索引，已排除项必须可见；没有就写“无”。只记录报告的开始和结束时间，不必每条问题单独计时。

按输入文件建立本次范围内的章节覆盖索引，与检查进度共用一张表：综合检查覆盖编制依据表、标准引用表、前言、正文和附件；单项检查覆盖相关载体及必要的跨章节证据。范围内的每个区域都要安排进批次，不能只按清单或评分项分批。目录的结构覆盖或已冻结状态不代替正文证据，本次投标响应位置和满足判断均重新核查。

## 3. 初步检查：清单覆盖

### 建立基线

- 先在项目档案和已有输出中定位当前版本、已核对的 `工程量清单.md`，有效就必须复用；记录其路径、来源版本、已记录哈希、BOQ ID、原行标识和计数单位，再对照原文核查分组起止、跨页衔接和澄清带来的变动。要停用旧基线的，记录失效依据和新旧差异；不能因为重新数一遍更方便，就换掉旧基线。投标响应位置和判断由本次检查重建。
- 没有有效清单时，在报告内从招标工程量清单、设备或服务清册提取，再按原顺序做第二遍回查。不分配 BOQ，不调用目录生成和冻结流程。品牌表如果只是对已有条目的选用限制，关联原行，不重复计数。
- 每行保留 BOQ ID（有基线时）、原编号、分类路径、名称、能区分同名项的特征、单位、数量、适用周期和来源；跨页续文并入原行，表头不计数。无法确认的行或分组保留待核，未知数量不填零。
- 找不到正式清单时，查功能等价的清册；候选有歧义时询问。用户确认确实没有清单的，记“不适用”并写明替代依据；标准/完整模式继续检查其他要求，初步模式要明确说明给不出清单覆盖结论。

### 对照与统计

把范围内每一行及其分点对应到报价、技术正文或附件证据。允许多个条目共用一张响应表，也允许同义名称；但要以特征及证据确定对应关系，不能只凭标题或笼统承诺就判完整。先提取要求的比较关系：精确值、至少、不超过、区间或允许偏差；单位换算后依原文判断，关系或允许偏差不明时记待核。

一行可以关联多个问题。行级主状态只用于统计，按以下顺序判定：

1. **矛盾**：已有明确证据表明不满足要求，或投标内部冲突。
2. **无法核实**：没有已证实的矛盾，但来源、附件或范围外依赖使判断不完整。
3. **遗漏**：相关投标正文、表格和附件都已查完，整行没有响应。
4. **部分响应**：有响应，但已确认缺少分点，或缺本次范围内商务/技术中必要一侧的内容。
5. **完整响应**：范围内全部要求都有可定位且满足条件的证据。

没查完的行先记“未查”，不得提前判遗漏。分点逐项记在核对表，父行按上面的顺序汇总；分点不重复计入清单总行数。数量冲突、缺分点、附件不可读等多个缺口都保留，不被主状态吞掉。

统计单位沿用已核基线的有效清单行，无有效基线时使用本次已回查清单行；这里的“父行”只指核对分点所属的清单行，不是任意上级分类标题。各批次按 BOQ ID（有基线时）或原行标识映射、去重后汇总，不能把清单行、分类父项、技术分点、评分项和合同义务混在一起加。已判五类之和加未查行数等于范围内总行数；范围内、范围外、不适用合计等于全基线或本次清单总行数，来源不明分组另列。新旧口径不同先逐项解释映射；无法闭合则不得声称清单检查完成。阶段性“完整响应”仅指本次纳入的一侧及分点。

## 4. 标准检查：要求与证据逐项核对

执行标准或完整模式时，必须读取 [标准检查类别](references/check-categories.md)，按其中的门槛、独立义务、报价、联合体、评分、正文、一致性、多分册、证件和图片规则逐项核对。完整模式还须执行第5节。

优先复用当前有效 `标书目录.md` 的全量 REQ 索引和来源覆盖，记录基线版本及哈希；缺失、失效或与原文冲突时在报告内重建受影响部分并记录来源位置，不分配 REQ，不调用目录生成或冻结流程。范围内相关的招标正文和附件都要覆盖；参考文件只读涉及的背景和事实部分，不能增加招标要求。同一要求在多处出现时关联来源，不重复计算问题。

### 版式与扫描件识读

- 文本提取只用于定位。报价、财务及其他跨栏表格须渲染原页，必要时按列裁剪放大；按单元格边界记录空白，不把邻行、邻列或其他表的数值补入空白单元格。比较不同表格时先核对字段含义和角色。
- 证件日期、报价数字、财务数据和其他决策关键扫描页须逐页视觉识读；低分辨率内容检测或抽样只能证明非空白/辅助分流，不等于文字和证据已核。其余扫描页只有用户明确接受抽样时才可按抽样范围结案，并须记录方法、页段和未逐页目验范围。
- 页码统一以物理页为准；印刷页码与物理页不同时记录映射，关键证据不得只写提取文本行号。实际提取与分页校验按 [大型文档并行与续查](references/large-document-review.md) 的页码约定登记。

## 5. 完整检查：引用核验

综合完整模式先完成标准检查；只做引用核验时，直接执行本节相关核对。登记本次范围内招投标文件中的法规、规范、标准编号/年份及外部引用文件，去重后逐项查询官方发布机构或权威数据库，记录查询对象、来源链接、查询时间和结果（已确认存在 / 信息不一致 / 无法确认）。只对照招标原话、不涉及外部引用时，直接核对原文件和响应，不增加外网查询。

逐行覆盖编制依据表、标准引用表和正文中的引用与转述，不能只搜标准编号。除了名称、年份和存在性，还要核对引用涉及的等级、阈值、单位和适用条件。实质偏差必须定位到适用版本的原文条款；只能查到目录信息时，存在性核验和内容核验分别记结果，后者保留待核。旧报告作为复核输入时，其中的候选问题也要逐项核实或排除，不直接沿用结论。

查不到不等于不存在；只确认存在，也不代表现行有效或适用。引用冲突记录影响，不擅自用查询结果改写招标要求。外部项目附件拿不到时保留盲区，不用同名的网络资料替代。

对适用且存在权威公开查询渠道的证件增加官方状态核验，分别记录文件日期状态与外部状态、查询日期和来源。查不到、需登录/验证码或网站不可用时记无法确认，不据此认定无效或造假；外部结果不擅自改写招标要求。

## 6. 证据与结案

所有模式都必须读取 [证据分类与覆盖结案](references/evidence-and-completion.md)，按其中规则区分文件内事实、招标符合性和准备提示，并分别验证来源覆盖与结果计数。

确认问题须有对应证据：缺失是招标要求加已查投标范围；偏差是要求加投标响应；内部矛盾是相互冲突的两处投标证据；无来源事实是陈述加已查材料范围。过期、未生效或期限不覆盖问题须同时保存要求基准日、证件日期和来源位置。不可见材料保留“待核/待人工核实”，不得作为已确认缺失。

已确认问题填写类别、严重级别、关联核对项、上述证据、说明、修改建议及置信度（高/中，注明证据限制；低置信保留待核）。明确违反门槛/否决依据才标“阻塞”；明确评分风险标“影响得分”；其他已证实问题标“一般”。只有假设中的评分关联或条款属性未知时不得标“影响得分”。清单遗漏或证件过期不自动等于否决；同一问题涉及多个后果只记一次并列出关联。排除主观文风意见，保留有证据的矛盾。

未获用户同意评分时，只列招标满分、条件和满足状态，不给预计得分、区间或“确定归零”；可去重汇总缺口涉及的招标分值，并注明不是预计失分。用户选择评分时，按 `bid-scoring` 给出可复核预计分或区间，单列依据、适用范围和不确定因素，缺失材料或外部参数不得直接计零。空章数量、字数和问题条数不代表方案质量或严重性。

结案前用工具复核：本次范围内各来源区域都有进度记录；分类覆盖表包含所有适用类别及实查方法，任何应检类别存在未查项时整体不得标“已完成”；全量表含正常项证据；REQ/BOQ 引用能在所记录基线中定位；本报告未限定来源的 C/P 引用均有对应明细，跨报告旧问题注明报告或版本来源；问题、待核、提示和已排除计数可由明细重算；涉及清单覆盖时按第3节闭合；声称相同或复用的输入有相同 SHA-256。证件和图片还须满足 [标准检查类别](references/check-categories.md) 的各自闭合条件。

满足上述条件则状态“已完成”，写结束时间、范围、问题数量和盲区。“已完成”只表示本次核查结束，不代表合规通过。用户明确接受抽样或部分范围时，未查部分保留且整体标“部分完成”；核心来源不可读、来源覆盖未知或独立检查未执行时标“未完成”。结论不承诺中标或不被否决。

## 7. 续查与整改复核

- **中断续查**：先读报告的输入版本、模式或单项类别、范围、独立性、全量表、分类覆盖和进度，核对续用条件都一致后，在同一篇报告继续，从下一处位置开始，保留编号。不要只读问题摘要就重查全套；不得靠对话记忆恢复。任一条件变化时新建报告并记录变化，旧判断必须在本次范围内复验后才能带入。
- **整改复核**：用新的独立检查上下文、新的时间戳报告，沿用原问题编号，只核对原问题及受改动影响的要求和交叉引用。记录已解决/部分解决/未解决/用户接受及证据；用户接受不等于符合要求。新发现的问题使用未占用的编号。影响范围无法确定时，扩大相关范围并说明，不声称完成了全套重审；原报告保留。
- **多报告结论不一致**：按“类别＋对象＋原页位置”归并同一事实，保留各报告编号，不按报告数量、模型来源或问题总数投票。逐项对照招标原文、原始版式和可重算证据，记录采纳、排除及待核依据；报告摘要和置信度不能代替原证据。发现原报告漏查的人员证件、附件或图片时扩大相应范围，已有“已完成”状态也须重新核验，不把不同 C/P 数量直接当作优劣。
