# 标书检查

以招标文件及有效澄清为最高依据，按用户选择执行初步、标准或完整检查。三种模式逐级包含；除项目建档外，不要求先运行目录、spec或撰写技能。检查者只读输入文件，唯一允许写入的产物是本次检查报告。

## 1. 确认项目、输入与模式

- 直接调用时先读取项目 `AGENTS.md`。不存在，或发现新增、消失、未登记文件时，使用 `招标项目建档`新建或更新，等待用户确认后恢复检查；流程调用时复用已确认档案。
- 列明项目目录、项目档案、全部招标文件及有效澄清、全部投标文件、已确认参考文件、用户事实素材和报告输出目录；spec存在时一并列明。旧版DOC、扫描件或特殊附件无法可靠读取时记录盲区，不猜测其内容。
- 用户已明确指定模式时直接执行；未指定时询问选择，不设置默认模式：
  1. **初步检查**：只检查工程量清单及分点遗漏。
  2. **标准检查**：包含初步检查，再完成文件内的全面核查。
  3. **完整检查**：包含标准检查，再核验招标文件中的外部引用是否能够确认存在。

完成标准：模式、招标文件版本、输入文件和输出目录均已确定，每个输入已分类或列入盲区。

## 2. 建立独立检查上下文

若当前是主代理，先按第3节创建报告，再创建一个不继承撰写对话的全新检查子代理，传入第1步的文件清单、模式、报告路径和“读取标书检查技能后执行”的指令。若任务已由检查子代理承接，直接继续，不再派生代理。

子代理机制不可用时停止，将已创建报告标为“未完成”并说明原因；主代理自查不是等价替代。

## 3. 立即建立检查报告

检查开始即按本机当地时间创建 `投标输出/<项目名>/标书检查报告-YYYYMMDD-HHmmss.md`，不得覆盖既有报告；同秒重名时依次追加 `-02`、`-03`。先写入：

```markdown
# <项目名> 标书检查报告

- 检查模式：初步检查 / 标准检查 / 完整检查
- 开始时间：<YYYY-MM-DD HH:mm:ss 时区>
- 当前状态：进行中
- 招标文件版本：<文件、版本或日期>

## 输入、范围与盲区
## 工程量清单覆盖统计
## 待核问题
## 已确认问题
## 已排除记录
## 结论
```

检查过程中每发现一个候选问题，立即写入“待核问题”，编号 `P-001` 起，并记录发现时间、招标位置、投标位置、缺失证据和当前状态。证据闭合后原位更新状态并转入“已确认问题”；排除后在“已排除记录”保留编号、核销依据和时间，防止重复检查。不得等全部检查结束后才首次写报告。

若检查中断、核心文件不可读或独立检查无法继续，保留已写内容，将当前状态改为“未完成”，列明停止位置和未检查范围。

## 4. 初步检查：工程量清单逐项覆盖

### 4.1 确定清单基线

- 先查项目内是否已有与当前招标文件及有效澄清版本一致、状态为“已核对”的 `工程量清单.md`，以及与当前投标文件集一致的清单行到投标内容落点映射。两者有效时直接复用；缺少、存在待核项或版本不一致时不得沿用旧结论。
- 无有效产物时，复用 `标书目录整理` 的清单提取与二次回查规则，直接从招标文件的工程量清单、设备清册、服务清单、品牌表及有效澄清逐行建立本次检查基线；不得从参考文件、既有目录或投标文件反推。
- 清单行至少保留原编号、分类路径、名称、区分同名项所需的项目特征、单位、数量、服务周期、来源位置。分组标题、表头和参数续文不得计作有效行；不能确认的行标为“无法核实”，不得假定完整。

### 4.2 对照投标文件

按招标顺序核对每个有效清单行及其下级分点在商务报价和技术响应中的证据，检查名称、分类路径、项目特征、单位、数量、服务周期和技术响应落点。每行只能归入以下一种状态：

- **完整响应**：报价及技术内容均有可定位证据，且关键字段一致；招标文件明确不要求其中一类响应时，在依据中说明。
- **部分响应**：存在落点，但缺少部分分点、关键字段或必要的商务/技术一侧证据。
- **遗漏**：在已检查的目录、正文、表格和附件范围内均未找到响应。
- **矛盾**：投标证据与招标清单，或投标文件相互之间的名称、特征、单位、数量、周期等不一致。
- **无法核实**：附件不可读、清单来源含混或证据受外部状态限制。

在报告中持续更新总行数及五种状态数量，并列出所有非“完整响应”行的清单来源、投标落点和缺口。不得仅凭总数、章节标题或笼统承诺判定覆盖完成。

完成标准：每个有效清单行及下级分点都有唯一状态，五种状态合计等于清单总行数，所有非完整项已落入报告。

## 5. 标准检查：文件内全面核查

先完成初步检查，再完整读取招标文件、投标文件和已确认参考文件：

- **否决投标风险**：核对形式、资格、响应性、固定格式、投标保证金、签章要求、必备附件和明确否决条款；“项目废标事项”与当前投标被否决分开表述。
- **评分损失风险**：按 `标书评分` 的完整评分检查分支逐项核对，不模拟评分，结果写入本报告。
- **矛盾与引用准确性**：核对正文、人员表、设备表、进度表、报价表和附件之间的一致性；逐项复核投标文件引用或转述的条款、文件名、数字、单位、阈值、精度和技术参数。
- **事实与待补**：定位无用户素材支持的资质、业绩、人员、参数、获奖、价格、交期和承诺；spec存在时核对其门槛、评分点和待补是否落实。

参考文件只用于核实背景事实和投标陈述，不得增加或改变招标要求。参考文件、既有目录、spec或其他产物与招标文件及有效澄清冲突时，绝对以后者为准，并把冲突写入报告。本模式不查询互联网或外部数据库，文件内无法确认的内容列入盲区。

## 6. 完整检查：外部引用存在性核验

先完成标准检查，再枚举招标文件中出现的法律法规、规范、标准、标准编号、版本年份、引用文件和外部附件，逐项核验：

- 优先使用政府部门、标准发布机构或官方数据库，核对引用是否能够确认存在，以及编号、名称、年份是否对应。
- 报告记录查询对象、权威来源、链接、查询时间和结论；投标文件中的引用也按同一口径核对其准确性。
- 找不到权威证据时标为“无法确认”，列明已查询范围，不得据此断言引用不存在。
- 招标文件引用内容与参考文件冲突时仍以招标文件为检查依据，同时记录冲突及其可能影响。

完成标准：每项外部引用都有“已确认存在 / 信息不一致 / 无法确认”状态和可复核查询记录。

## 7. 证据、分级与收敛

候选问题进入“已确认问题”前必须具备匹配证据：

- 清单缺失或矛盾：招标清单行及来源 + 已检查的投标范围或冲突投标证据；
- 否决、评分或引用问题：招标原文或评分标准 + 投标证据；
- 内部矛盾：相互冲突的投标证据A + 投标证据B；
- 无来源事实：投标陈述 + 已核查但未发现支持材料的事实素材范围。

扫描图片或附件不可见时使用“待人工核实”，不判定材料缺失。只有存在明确门槛或否决依据时，严重级别才写“阻塞”；有明确评分条件但证据不足写“影响得分”；其他事实矛盾、未登记待补或高置信文字错误写“一般”。清单遗漏本身不得自动等同于否决投标。

每个已确认问题沿用候选编号并补齐：类型、严重级别、两项证据、招标依据、问题说明、修改建议、置信度和确认时间。删除主观文风意见和重复问题，但不得删除有证据的内部矛盾。

检查完成后将报告状态改为“已完成”，写明结束时间、工程量清单覆盖统计、问题数量、盲区和结论。结论不得承诺中标或“不废标”。

## 8. 整改复核

用户要求复核时使用新的独立检查子代理，并创建新的时间戳报告。读取原报告和整改后的相关文件，沿用原问题编号，只复核原问题及受修改影响的清单行、评分点、数字和交叉引用，记录“已解决 / 部分解决 / 未解决 / 用户接受”及复核证据；不得改写或覆盖原报告。
