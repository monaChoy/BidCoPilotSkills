# 标书检查

目标是用完整文件检查发现可举证的否决投标风险、评分损失风险和内容质量问题。除项目建档外，不要求先运行目录、spec或撰写技能；已有产物仅作可选辅助。进入检查阶段后，检查者只读招标文件与投标文件；唯一允许写入的产物是检查报告。

## 1. 确认项目与完整输入

- 直接调用时，先读取项目 `AGENTS.md`。不存在，或发现新增、消失、未登记文件时，使用 `招标项目建档`完成新建或更新，等待用户确认后恢复检查。
- 流程调用时复用已确认的项目档案。
- 输入必须列明：项目目录、项目档案、全部招标文件及有效澄清文件、全部投标文件、用户事实素材、报告输出目录；spec存在时一并列明。
- 支持用户确认的PDF、DOCX、MD、TXT及必要图片。旧版DOC或特殊附件无法可靠读取时列入检查盲区，继续处理可读文件。

完成标准：每个输入文件已分类为招标文件、投标文件、事实素材或检查盲区；没有身份不明的文件。

## 2. 建立独立检查上下文

若当前是主代理，使用子代理机制创建一个不继承撰写对话的全新检查子代理，并传入第1步的明确文件清单、输出路径和“读取标书检查技能后执行”的指令。若当前任务已经明确由检查子代理承接，直接继续，且不再派生代理。

子代理机制不可用时停止，报告“未完成独立检查”；主代理自查不是等价替代。

完成标准：检查工作运行在独立子代理中，或已明确停止并说明原因。

## 3. 范围轮

完整读取招标文件和投标文件，先写下：

- 本次能够判断的文件与事项；
- 不可读文件、未提供附件和依赖外部状态的检查盲区；
- spec是否存在；存在时增加“spec决策是否落实”，不存在时不阻塞检查。

签章真伪、密封、CA、平台上传和现场递交等不能由当前文件可靠判断的事项进入检查盲区。关键资格、响应性或评分标准不可读时，最终报告不得给出对应维度“未发现风险”的结论。

完成标准：检查范围覆盖全部已确认文件；每个未覆盖部分都有具体原因和影响。

## 4. 核查轮

先完成三道主检：

1. **废标检查（报告用语：否决投标风险）**：核对形式、资格和响应性评审条款；“项目废标事项”与当前投标被否决分开表述。
2. **矛盾检查**：核对同一章节、同一文件不同章节、不同投标文件，以及正文与人员表、设备表、进度表、报价表、附件之间的一致性。重点比较项目名称、人员、设备型号与数量、工期、日期、金额、服务期限、技术参数和承诺。
3. **引用准确性检查**：逐项核对投标文件中引用、转述或声称来自招标文件、标准规范和参考资料的内容。检查是否断章取义、张冠李戴，并复核条款归属、标准名称与年版、数字、单位、阈值、精度、检出限和技术参数是否与原文一致；区分招标要求、参考资料事实和投标人自行承诺。

再完成配套核查：

- **评分损失风险**：按 `标书评分` 的流程调用分支执行评分检查，不进行模拟评分；结果并入本报告。
- **spec落实**：spec存在时，逐项核对计划落点、门槛、评分点和待补是否落实。
- **事实与待补**：定位无用户素材支持的资质、业绩、人员、参数、获奖、价格、交期和承诺；区分已登记待补、未登记待补和待人工核实；只报告高置信错别字。

发现阻塞问题后仍完成其余维度；只有核心文件完全不可读时才提前停止。

每个候选问题必须具备与问题类型匹配的证据对：

- 否决、评分或引用问题：招标原文或评分标准 + 投标证据；
- 内部矛盾：相互冲突的投标证据A + 投标证据B；招标依据只用于判断后果和严重性，不是保留该问题的前提；
- 无来源事实：投标陈述 + 已核查但未发现支持材料的事实素材范围；
- 缺失响应：招标要求 + 已检查但未发现响应的目录、章节、附件清单和正文范围；
- 未登记待补或错别字：准确投标位置 + 足以确认问题的上下文。

扫描图片或附件不可见时使用“待人工核实”，不判定材料缺失。

完成标准：三道主检和三项配套核查均有结论或具体检查盲区；每个候选问题都有匹配其类型的证据对。

## 5. 收敛轮与报告

去重并反查每个候选问题：删除无匹配证据的猜测、主观文风意见和重复问题。内部矛盾不因缺少招标依据而删除。按严重性分类：

- **阻塞**：有明确门槛或否决依据；
- **影响得分**：有明确评分条件但响应或证据不足；
- **一般**：事实矛盾、未登记待补或高置信文字错误。

写入 `投标输出/<项目名>/标书检查报告.md`：

```markdown
# <项目名> 标书检查报告

## 检查范围与盲区

## 问题清单
### C-001 <标题>
- 类型：否决投标风险 / 矛盾问题 / 引用准确性问题 / 评分损失风险 / 内容质量问题
- 严重级别：阻塞 / 影响得分 / 一般
- 证据一：<类型、文件、位置、必要短摘录>
- 证据二：<类型、文件或已核查范围、位置、必要短摘录>
- 招标依据：<适用时填写；内部矛盾等不适用时说明>
- 问题说明：
- 修改建议：
- 置信度：高 / 待人工核实

## 待补汇总核对
## 结论
```

报告结论说明自动检查的边界，不承诺中标或“不废标”。

完成标准：所有保留问题都有唯一编号和匹配其类型的证据对；所有检查盲区已披露；报告已保存并向用户摘要交付。

## 6. 整改复核

用户要求复核时使用新的独立检查子代理。读取原报告和整改后的相关文件，沿用原问题编号，只复核原问题及受修改影响的评分点、数字和交叉引用；在原报告增加复核结果：

```markdown
- 状态：已解决 / 部分解决 / 未解决 / 用户接受
- 复核证据：
```

完成标准：每个指定问题都有状态和复核证据，关联内容没有新增矛盾。
