# 大型文档并行与续查

大型标准/完整检查、内容与图片并行、子代理超时或失败接管时读取本文件。并行只改变调度，不改变用户范围、证据要求或结案条件。

## 角色与单一写者

- 用户直接调用检查且主上下文未参与撰写时，主上下文可作为独立主检查员。撰写后的检查必须由未参与撰写的独立上下文执行。
- 页数、图片对象数或上下文占用使单一代理难以分批完成时，主检查员可安排**内容 peer**与**图片 peer**并行；用户要求加速时也可采用。固定页数或图片数只作提示，不作为唯一触发条件。
- 主检查员创建共享工作目录、输入版本清单和主报告骨架，为每个 peer 指定范围与产物位置。
- 内容 peer 写内容核查工作稿；图片 peer 调用 `image-authenticity-review` 并只写独立图片报告及图片清单。
- **主检查员是主报告唯一最终写者**。peer 不同时编辑主报告，不共同维护统计或 C/P 编号。
- 图片 peer 使用图片报告内本地 ID；主检查员合并时按实际登记顺序分配主报告 C/P，并保留本地 ID 与 C/P 的映射。内容 peer 返回后也由主检查员核对并合并，不预留编号段。
- 主检查员交付前复核高风险项、分类覆盖、引用和统计，并对原始版式中的关键数字、日期和跨栏表格抽核。

## 派工契约

每个 peer 的交接至少包含：

- 技能路径、输入路径及 SHA-256；
- 已选模式、模拟评分选择、纳入/排除范围；
- 主报告路径、自己的工作稿或配套报告路径；
- 已验证的物理页映射、无文本扫描页清单；
- 当前批次、落盘频率、下一处位置；
- 只读输入、不得扩大或缩小范围、不得由超时推断完成。

peer 先创建自己的报告骨架，每批保存正常项、异常项、证据位置和下一处位置。图片 peer 另行保存登记数、元数据读取数、视觉初筛数、深查数和未初筛清单。

## 超时与失败接管

- 时间或上下文预算只触发**保存并返回进度**，不减少应查范围，不改变完成条件。
- 返回内容包含已完成批次、已落盘位置、未查清单和下一处位置；零产出也明确报告，不把对话摘要当作已保存证据。
- peer 超时或失败后，独立主检查员可从最后已保存位置接管，或安排新的未参与撰写上下文续查。
- 主报告的分类覆盖与执行记录分别写明各执行者及其实查范围。子代理失败后的接管标为“独立主检查员接管，子代理未完成”或实际情况，不声称子代理已完成。
- 撰写方不能因 peer 失败而接管检查；此时报告“未完成独立检查”。

## 文本提取与物理页映射

- 文本提取用于定位。需要分页文本时优先采用环境已有、能保持版式的工具，例如 `pdftotext -layout`；记录实际工具、版本或命令及输出位置。
- 按换页符分页后，抽查首尾页、跨页表格和至少一个中间页，建立提取分段与物理页的映射。`chunk p-1 = 物理页 p` 只有在本文件已验证时才可使用，不作为所有 PDF 的固定规则。
- 登记无文本扫描页；这些页须渲染识读，空白提取结果不证明页面无内容。
- 未分页文本不能作为页码锚点。关键证据以物理页和原始版式为准；印刷页码不同则同时记录映射。
- 续查先核对输入哈希和已有映射，不因更换代理而默认沿用未验证的分段关系。
