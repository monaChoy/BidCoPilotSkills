# 大型文档并行与续查

大型综合或单项检查、内容与文件痕迹并行、子代理超时或失败接管时读取本文件。并行只改变调度，不改变用户范围、证据要求、固定文件痕迹分支或结案条件。

## 角色与单一写者

- 用户直接调用检查且主上下文未参与撰写时，主上下文可作为独立主检查员。撰写后的检查必须由未参与撰写的独立上下文执行。
- 页数、文件对象数或上下文占用使单一代理难以分批完成时，主检查员可安排**内容 peer**与**痕迹 peer**并行；用户要求加速时也可采用。固定页数、文档数或图片数只作提示，不作为唯一触发条件。
- 主检查员创建共享工作目录、输入版本清单和主报告骨架，为每个 peer 指定范围与产物位置。主报告骨架须按「结论 / 问题记录在前、过程表与底表在后」；合并时先更新文首结论（含痕迹与图片摘要）与问题记录，再写入后置明细。
- 内容 peer 写内容核查工作稿；痕迹 peer 调用 `file-trace-review`，由该技能统一执行文档和图片分支，只写配套痕迹报告、机器摘要及子技能产物。
- **主检查员是主报告唯一最终写者**。peer 不同时编辑主报告，不共同维护统计或 C/P 编号。
- 痕迹 peer 使用痕迹报告内 T ID 及图片报告本地 ID；主检查员合并时按实际登记顺序分配主报告 C/P，并保留本地 ID 与 C/P 的映射。内容 peer 返回后也由主检查员核对并合并，不预留编号段。
- 主检查员交付前复核高风险项、分类覆盖、引用和统计，确认文首结论已含痕迹/图片结果且与后置「文件痕迹检查」一致，并对原始版式中的关键数字、日期和跨栏表格抽核。
- 并行时仍由**主检查员**更新综合检查的会话 Todo（阶段切换、进行中唯一项）；文案保持业务中文。痕迹 peer / 内容 peer 维护各自清单，不抢写主清单。

## 派工契约

每个 peer 的交接至少包含：

- 技能路径、输入路径及 SHA-256；
- 已选模式、模拟评分选择、纳入/排除范围；
- 主报告路径、自己的工作稿或配套报告路径；
- 已验证的物理页映射、无文本扫描页清单；
- 当前批次、落盘频率、下一处位置；
- 只读输入、不得扩大或缩小范围、不得由超时推断完成。

peer 先创建自己的报告骨架，每批保存正常项、异常项、证据位置和下一处位置。痕迹 peer 另行保存文档输入数、解析状态数、失败及未支持项，以及图片登记数、元数据读取数、视觉初筛数、深查数和未初筛清单。

## 超时与失败接管

- 时间或上下文预算只触发**保存并返回进度**，不减少应查范围，不改变完成条件。
- 返回内容包含已完成批次、已落盘位置、未查清单和下一处位置；零产出也明确报告，不把对话摘要当作已保存证据。
- peer 超时或失败后，独立主检查员可从最后已保存位置接管，或安排新的未参与撰写上下文续查。
- 主报告的分类覆盖与执行记录分别写明各执行者及其实查范围。子代理失败后的接管标为“独立主检查员接管，子代理未完成”或实际情况，不声称子代理已完成。
- 撰写方不能因 peer 失败而接管检查；此时报告“未完成独立检查”。

## 文本提取与物理页映射

- 文本提取用于定位。需要分页文本时优先采用环境已有、能保持版式的工具，例如 `pdftotext -layout`；记录实际工具、版本或命令及输出位置。
- 按换页符分页后，抽查首尾页、跨页表格和至少一个中间页，建立提取分段与物理页的映射。`chunk p-1 = 物理页 p` 只有在本文件已验证时才可使用，不作为所有 PDF 的固定规则。
- 登记无文本扫描页；这些页须渲染识读，空白提取结果不证明页面无内容。
- 未分页文本不能作为页码锚点。关键证据以物理页和原始版式为准；印刷页码不同则同时记录映射。
- 证据引用写法见 [证据分类与覆盖结案](evidence-and-completion.md)；分段号仅可作括号内辅助锚点。
- 续查先核对输入哈希和已有映射，不因更换代理而默认沿用未验证的分段关系。

## 增量渲染与批量复核

- 先读 `检查状态.json`，只渲染未查页或需要复核的关键页。已有全文、图片和逐页产物须通过输入、范围、工具契约及产物哈希验证后复用；历史报告不自动成为当前报告。
- 同类多页可用带物理页码的 2–4 页对照图或关键栏裁剪分流。金额、日期、编号、签章及其他决策关键值仍须以可读原尺寸复核，不用缩略图猜读。
- 红框/标注残留优先复用已有页面证据或使用环境已有的 PDF 对象能力；没有适用对象解析能力时记录方法未覆盖，不做低 dpi 全册渲染盲扫。
- 开工记录范围、深度和完成条件。状态索引只减少重复，不允许为提速把默认完整覆盖自行降为抽样。

## 同输入重核（产物可复用，结论须本轮重验）

输入 SHA-256 与范围未变、再次做独立检查或完整重核时：

**允许复用（须校验哈希/范围/工具契约）**：痕迹包与机器摘要、图片接触表与初筛清单、清单基线行、已落盘外部标准查询 CSV、已验证分页映射、ActiveX 勾选 JSON（核对其 `input_sha256` 与本轮招标 DOCX 一致）。复用须在报告写明路径与哈希。

**禁止直接复用**：旧报告的问题结论、严重级别、明暗标判定、模拟分数字、已排除理由（可作为候选线索，必须本轮对照原件重验后才能写入新报告）。

**明暗标待核例外**：旧报告对该勾选/明暗标为待核或冲突时，本轮**继承待核状态**（不是复用「已确认」结论）；先问用户或 Word 原件目视，满足勾选态「闭合门」升格条件后才可改写为已确认暗标/明标。禁止「上一轮待核 → 本轮无问人直接已确认阻塞」。

**本轮仍必须满足（覆盖不降）**：

- 分类覆盖表每个适用类别有本轮执行记录与方法；
- 全部高风险 / 待核 / 阻塞（含潜在阻塞）候选对照原件复验；
- 对旧报告已确认问题按类别抽核：至少覆盖证件编号与日期、清单矛盾行、评分客观项、一致性关键页；抽核比例与对象写入报告；
- 任一输入哈希变化的类别 → 该类别全量重做，不得抽核了事。

独立检查仍须新建不继承撰写对话的上下文；「复用产物」不等于「复用结论」。
