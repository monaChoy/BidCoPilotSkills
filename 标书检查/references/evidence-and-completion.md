# 证据分类与覆盖结案

本文件由 `bid-review` 的所有模式读取，用于约束结论强度、无招标文件分支和覆盖结案。

## 三类结果

每行核对先区分下列结果，不用一个“满足”混合表达：

1. **文件内事实**：原始版式、附件、可重算输入或两处投标证据直接证明的数值、日期、空白、差异、软件字段等。写清观察对象和位置。
2. **招标符合性**：只有适用招标条款、比较关系和投标证据齐全时，才判满足或不满足。缺招标文件或条款时写“招标符合性无法核实”，可同时保留文件内事实。
3. **准备提示**：临期、纯重复、软件保存记录、版本年份未载明及其他没有违反要求证据的事项，写入“准备与临期提示”或质量建议，不计为已确认缺陷。

事实存在不等于问题成立。问题计数、待核计数、提示计数和已排除计数分别汇总。

## 无招标文件分支

用户明确没有招标文件时，范围名称写明“仅内部质量与证据检查，招标符合性未检”或同等限制。可以检查：

- 报价算术、大小写和表内勾稽；
- 内部一致性、证件日期状态和附件对应；
- 图片编码、元数据和视觉线索；
- 投标目录与实际标题、页段的对应。

投标目录只能作为自身结构索引，不能作为招标完整性基线。不得创建虚构 REQ/BOQ，不得判资格、否决、评分或招标意义上的完整响应。结论写“目录所列章节已定位”等实际结果，不扩展为“章节齐全”“完整响应”或“满足要求”。

## 常见结论边界

- 空白单价、零合价先记事实；漏填、零报价或费用含在其他项中须由报价说明或招标规则确定。邻项价格只作待核线索或情景演算，不写成应改金额。
- 计价口径有歧义时，并列输入、公式和结果，不以“倾向”替代原文依据。
- 临期只提示准备风险；另有证据证明在要求基准日失效时，才按相应问题登记。
- 未注标准年份、纯重复、PS 软件字段在没有违反要求证据时不计缺陷；红框等实际编辑残留可记质量事实，但仍不自动等于内容篡改。
- 联系方式、成立日期、服务期等先核对主体、字段、用途和计数口径；不同用途号码、历史沿革与法人登记日期不自动构成矛盾。
- 已排除误报保留原位置、排除理由和复核证据，不计入当前问题。

## 来源覆盖与结果计数

“分类覆盖与执行记录”至少包含内容要求、报价、企业证件、人员证件、财务、业绩、一致性和图片；本次不适用或范围外的类别写明依据。每类记录：

- 应查文件、页段、附件或对象集合；
- 实查范围、方法和执行者；
- 未查项及原因；
- 未查 / 抽核 / 已查 / 待核 / 范围外状态。

全量核对表只登记实际完成的核对，C 行数及其结果分类之和只证明结果计数可重算。来源覆盖必须由页段、附件、清单行、证件对象和图片对象等各自明细闭合，不能用 C 行数代替。

同类正常项可汇总，但清单行、证件及其他需要双向闭合的对象必须在明细表逐项可追踪。抽核只能形成抽核范围结论；标准/完整模式默认完整覆盖。用户明确接受抽样时，报告标注“抽样检查”，整体只能为“部分完成”，不能声称标准全套检查完成。

## 整体状态

- **已完成**：所有适用类别均已按模式完成，来源覆盖与结果计数分别闭合，证据引用可回指，未查项为空。
- **部分完成**：用户明确接受抽样或部分范围，或者其他类别已有可用结果但仍有未查项；报告显著列出未完成范围。
- **未完成**：核心来源不可读、来源覆盖未知、独立检查未执行，或本次没有形成可交付的完整类别结果。

外部不可得、原件不可读或方法不支持才列盲区，并只阻塞受影响的判断；应检未检不列入盲区。任何应检类别存在未查项时都不得标“已完成”。
