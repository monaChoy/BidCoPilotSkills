# 标准检查类别

本文件由 `bid-review` 的标准、完整及相关单项检查读取。要求依据只来自招标文件及有效澄清；参考文件只提供背景和事实。

## 要求与证据类别

- **门槛**：须知前附表、否决条款、形式/资格/响应性评审、实质性标记条款、合同专用条款中的适用门槛，以及固定格式、签章占位、保证金、必备附件。记录要求、适用条件及投标证据；结果为满足/不满足/无法核实。项目废标和本投标被否决分开表述。
- **独立技术与服务义务**：逐项提取未被清单或评分覆盖的技术标准、接口、交付资料、验收、培训、备件、运维等要求，包括被引用的项目附件。不得以“不计分”或“不在清单”为由跳过。结果为满足/部分满足/未发现/无法核实。
- **报价**：限价、唯一性、大小写、单价乘数量、合价汇总，以及招标规定的暂列金额、暂估价和不可竞争费。用计算工具核对算术，保留输入和公式；遵循原文的计价、税率和舍入规则，规则不明的先记待核。空白或零单价先记录事实并查填列规则，不凭邻表数值补判矛盾或给出应改金额。含税/不含税等口径按原文确定；确有歧义时并列可重算结果，不添加无依据倾向。
- **联合体**（适用时）：协议及分工、成员资格与业绩认定、己方和其他成员接口、未补材料。
- **评分**：读取 `bid-scoring` 的基准提取和正文评分检查分支，传入本次范围及用户是否需要模拟评分的选择；全部核对结果并入主报告。用户选择需要时，再执行其模拟评分分支，在主报告单列“模拟评分”小节；否则只核对满足程度，不预测分数。不另建评分报告。
- **正文是否存在**：按 `bid-scoring` 的正文识别规则实测疑似空章，保存章节边界、排除项、有效正文字符数及非文本材料状态；目录、标题和占位词不能算正文。先核对分册分工及其他位置的实质响应，不能把一个分册的空章直接判为整套遗漏。
- **一致性与事实**：核对正文、人员、设备、进度、报价及附件中的相同事实和引用，包括企业成立日期、联系方式、体系标准编号/年份、服务期、资质表与附件、信用证明及人员证件。只有对象、字段、场景和口径相同才判冲突；历史沿革与法人登记、不同用途联系方式、不同角色分别记录。服务期等期间计算先核对原文计数口径，口径不明时并列含首末月与不含首月的差异。资质、业绩、参数、承诺等无素材支持时记证据不足，不直接认定造假。若存在 `投标输出/<项目名>/关键参数台簿.md`，将台簿中的关键参数与正文、附表对照；同名参数取值冲突列入本类问题，并定位台簿行与正文位置。
- **身份与明暗标**：先取项目档案「技术文件编制方式」；无档案或与原文冲突时按下述判定，判不出则按明标并记「按默认明标」。**判定顺序（项目专选优先；禁止模板条款反压）**：(1) 先区分前附表「无明暗标勾选项」与「有勾选项」——无此项走 (3)；有此项以勾选为准，不得用后文模板条件句改判。(2) **有勾选项时按勾选态判定阶梯**（先机器；触发闭合门则待核并一次问人；详见下方）：已勾选「技术标暗标评审」等且未触发闭合门 → 暗标；明确未勾选或勾了非暗标项且未触发闭合门 → 明标/非暗标，并记录「前附表该项未勾选/已勾××」及判定方法。(3) 无勾选项：仅当出现项目专句（如「本项目技术标采用暗标」）或等效禁止投标人名称/标识/业绩/人员信息 → 暗标；出现技术标明标、须载明投标人名称 → 明标；都没有 → 未明示按明标。(4) 冲突与闭合门：控件值与「本项目采用暗标」专句冲突、同组互斥控件冲突、上一轮待核未问人、或 Word/人眼与机器不一致 → 待核，**优先问用户一句**（或请其用 Microsoft Word 目视确认），不擅自定暗/明，不启动 GUI 长链路，不据此登记身份阻塞。模板中「暗标格式要求」「暗标评审部分不得出现名称…」等条件句，只在已判定为暗标时生效，**不得**单独作为暗标依据，也**不得**压过前附表未勾选。(5) **不得**因电子投标工具、防串标序列号、分册递交推断暗标。**暗标**：本条仅适用于招标要求暗标的范围（通常技术标分册；招标原文未按分册区分时适用全部技术文件）：正文与图表中的本单位名、自指（我院/我公司等）、人名、可识别证书号、自指业绩等命中 → 作为阻塞级候选（须有命中位置证据）；未要求暗标的其他分册（商务、资格等）按明标规则处理，其中的本单位名称属正当表述。招标方联系方式等招标原文信息不按投标人身份泄露计。**明标 / 非暗标**：本单位正当表述一般不记缺陷，不得登记「暗标分册边界」「暗标身份泄露」类问题；他单位名、竞争者名称被当作己方能力背书写入 → 记问题。拿不准的标待核，不猜。

### 勾选态判定阶梯（前附表明暗标等）

有勾选项时按下列顺序取态；核对行证据须写清文件名、前附表项号与所用方法（ActiveX / 内容控件 / Wingdings交叉验证 / 用户确认），禁止只写「已目视」。

1. **ActiveX Forms.CheckBox（优先）**：对招标 DOCX 先运行  
   `python3 -B scripts/extract_activex_checkboxes.py --json --darkbid-only <招标文件.docx> -o <工作目录>/activex_checkboxes.json`  
   （必须带 `--json` 或 `-o …json`；**禁止** `python3 … > xxx.json` 不带上述参数冒充 JSON——此时 stdout 是文本）。读取 Caption、控件名与 Value（`-1`/`true` 为已选，`0`/`false` 为未选）；同组选项对照。产物须含 `input_sha256`；复用时与本轮招标 DOCX 哈希核对。有可读 ActiveX 结果且**无下方「闭合门」触发项**时，以此定勾选，不再为勾选去渲染 LO/WPS 页或开 Computer Use。  
   **`--darkbid-only` 为 0 条时**：看 JSON 的 `total_checkbox_count`——若全量仍有控件，须去掉该开关再跑一次全量复核，确认前附表确无明暗标相关勾选项后再走下方「无勾选项」专句路径；不得把「关键词未命中」直接当成「文档无复选框」。
2. **内容控件**：无 ActiveX 时读 OOXML `w:checked` / `w14:checked` 等。
3. **Wingdings / 符号格**：仅当无 ActiveX、无内容控件时使用；须与同组已明确勾选项交叉验证，不得单凭提取文本中的 ☐☑☼ 定论。
4. **冲突或不可解析**：控件互斥冲突、与项目专句冲突、或上述方法均不可靠 → 待核，一次问用户（或 Microsoft Word 原件目视）；两种机器方法仍冲突时停止再加工具。
5. **闭合门（防假阻塞）**：下列任一成立时，勾选结论只能记 **待核**，并**一次问用户**（或请其用 Microsoft Word 打开原件看该项）；**不得**写成已确认暗标/明标，**不得**据此登记身份泄露类阻塞，也**不得**把上一轮待核无问人就升为已确认阻塞：
   - 同输入上一份检查报告对该勾选/明暗标仍为待核或冲突；
   - 用户已提供或本轮取得的 **Word 原件/人眼目视** 与 ActiveX（或其它机器）Value 不一致；
   - ActiveX 与「本项目采用暗标」等项目专句冲突，或同组互斥控件结论冲突（与第 4 点一致）。  
   **升格条件**：仅当「本轮用户书面确认」或「Microsoft Word 原件目视与机器结果一致」后，才允许把明暗标写成已确认，并据此做身份阻塞判定。
6. **禁止作为勾选主路径**：LibreOffice/WPS 导出页或内嵌 WMF/BMP 预览判定 ActiveX 勾选；Computer Use / GUI 自动化找勾选（仅当控件不可解析且用户不在场无法确认时才可尝试，且不得替代「一次问人」）。「禁止 LO/WPS 主路径」**不表示**可忽略 Word 原件/人眼与 ActiveX 的冲突——冲突走闭合门。
- **多分册**：逐一比对同名或同一要求的章节，区分空骨架、重复、互补和冲突。对会影响合并取舍的正文，用工具计算相似度并注明算法、去标题等预处理和比较范围；数值仅辅助，互补不能判冲突。查找编写者标签、待补、批注等残留，记录实际命中数及位置，只提出清理建议，不改输入。纯重复但无冲突、无内容丢失且无违反要求证据的，不列为当前缺陷。
- **证件与有效期**：核对企业及人员证照、资质/资格/许可证、体系认证，以及适用的授权书、保险、保函/保证金证明和其他有明确期限的文件；结果为满足/不满足/无法核实。无招标文件时只报告文件日期状态，招标符合性另记无法核实。
- **文件痕迹**：调用 `file-trace-review` 汇总文档元数据、隐藏修订、嵌入对象、XML 字段、文件指纹和图片结果，保留统一报告及覆盖状态；未发现线索不等于痕迹不存在。
- **图片真实性**：由 `file-trace-review` 统一调用 `image-authenticity-review` 检查扫描件和图片中的 PS 编辑、拼接、改字及 AI 生成/重绘线索，保留独立证据报告；结果为检出明确记录/发现可疑局部/本次范围未发现明确线索/材料不足或未检查。

## 证件与有效期核对

- 从资格、评分、人员、合同和附件要求反查所需证件，同时从投标附件正向盘点，防止只查正文列出的证件。同一证件多页和重复件归并，正常项也保留核对行。企业证件与人员证件分别在分类覆盖表登记应查和实查范围。
- 每件在“证件与有效期登记表”登记对象及主体、类型、编号、等级/专业/适用范围、发证机构、签发/生效/截止日期、附件位置、对应招标要求和比较基准；无对应字段记未载明，不补猜。登记表与全量核对表共用 C ID，不另编证件号。
- 按招标指定时点判断；未指定时以投标截止日为主要合规基准，并另列检查执行日状态。招标要求覆盖履约期时继续核对覆盖期间，不能用检查日或文件签署日替代要求日期；签署日只作辅助观察点。
- 区分在要求时点有效、已过期、尚未生效、期限不覆盖要求期间、未载明期限/长期有效，以及日期或附件不可读导致的无法核实。到期日当天是否有效依原文；只有日期时按当日有效，存在具体时刻或日期歧义则待核。
- 检查执行日有效、但在预计递交日或临期观察日及之前到期的证件，写入“准备与临期提示”，列到期日、观察日、剩余天数和续证/替换建议；检查日已过期按过期记录，不称临期。临期提示不替代招标基准判断，不单独计为已确认不符合。
- 搜索全套投标及已确认事实素材中的续证、换证和新旧证件；有满足要求的新证时，不因旧证同时存在直接判过期。新旧证主体、编号、期限或范围冲突时单独登记。
- 核对持证主体与投标人、拟派人员或联合体成员的归属及身份字段，以及招标要求的等级、专业、地域和许可范围；证件未过期不等于资格满足。
- 对投标有效期、授权期限、保险期间、担保/保函期限及招标明确的其他时限，记录起止日期、覆盖要求和计算结果；用工具复核日期差、时长及跨材料一致性。
- 扫描件缺页、遮挡、模糊或日期无法可靠识读时保留待核并列入人工核对，不猜日期，不判已过期或缺失。

证件结案须确认所需证件与实有附件双向闭合、每项有基准日和结果、日期及剩余天数可重算、续证已关联、临期提示已登记或明确为无、不可读及外部状态盲区已登记。人员证件只抽核时不得声称证件类别或标准全套检查完成。

签章真伪、密封、份数、截止时间、CA、上传及保证金到账等不能由文件确定的递交事项，按适用原文记录到人工核对清单；不把“需人工完成”写成已满足。标准模式不查外网，证件吊销、注销、暂停等外部状态作为盲区。

## 文件痕迹与图片真实性检查

- `file-trace-review` 是 `bid-review` 的固定伴随分支：综合初步/标准/完整、单项检查、旧报告续查和整改复核均须按本次纳入范围调用，默认技能路径为 `~/.agents/skills/文件痕迹检查/SKILL.md`，其他环境按技能 ID 解析。单项只查纳入载体，整改复核只查改动文件及受影响范围，不因此扩大其他类别；旧报告缺有效痕迹分支时必须补齐。大型文档的痕迹 peer 按大型文档编排引用执行。
- 传入原文件及哈希、纳入的文件或页段、可选合法对比文件、第三方报告和配套产物目录。痕迹总技能调用 `document-trace-review` 提取 DOCX、PDF、XML 和文件指纹，并统一调用一次 `image-authenticity-review`；本检查不再单独重复调用图片技能。
- 文档脚本默认只向模型交付 summary，完整 manifest 按需回查。解析失败、未支持格式、摘要截断和未覆盖方法分别保留；指纹、字段、RSID、时间戳和软件名称相同只记录事实及可能成因，不直接认定串标或不符合。
- 页段范围只限定图片所在页面，不再按图片类型挑选；范围内全部内嵌图片对象和独立图片均登记并逐图初筛。仅 logo、页眉页脚装饰和纯装饰底纹可不深入，仍须计数并记录依据；其他图片不得按类型排除。
- 按图片技能使用批量初筛脚本或等效流程生成逐对象清单及接触表。脚本提取、元数据读取和接触表生成不等于视觉初筛；执行者须查看全部完整接触表并回写每个对象的初筛状态。候选优先只改变审阅顺序，候选专用接触表只用于深查和续跑，不替代全量初筛。
- 相同源图可只深入分析一次，但全部引用位置保留，重复引用不减少初筛分母。在全部对象逐图初筛的基础上，再对疑点及证照、合同、签章、金额、日期和异常记录优先做原尺寸局部与完整页面复核。标书检查的视觉识读只用于内容核对，不代替图片编码、元数据、像素和文件结构检查。
- 同一输入及范围只调用一次；中断续查复用未完成的痕迹及图片报告，输入或范围变化时新建。结案前须用工具确认 `文件痕迹报告.md` 和机器摘要实际存在、可读取且哈希及范围匹配；图片报告、旧报告或 handoff 的文字声明不能替代。技能不可用、未调用或文件未生成时，主报告标“文件痕迹检查未完成”或“图片真实性检查未完成”，不得静默跳过或用普通页面浏览替代。
- 配套产物保存在主报告同级 `文件痕迹检查-YYYYMMDD-HHmmss/`，其中包含统一痕迹报告、机器摘要、文档清单和 `图片真实性检查/` 子目录；重名追加 `-02` 等。原始材料及证据留在本次工作目录，不上传外部服务。
- 主报告文首「结论」须写入痕迹与图片真实性摘要（分支状态、配套报告路径、分类统计与一句话业务结论、图片登记/初筛/复核与一句话结论）；后置「文件痕迹检查」保留完整字段：痕迹报告链接、业务结论及“建议处理/需要确认/准备解释/仅作记录/已排除”分类统计、文档解析状态、未支持项、痕迹应检哈希、T 与 C/P 映射，以及图片登记对象数 N、元数据已读数、视觉初筛数 X、原尺寸/整页复核数、唯一源图数及装饰类排除数。文首与后置状态、路径和统计须一致。检查执行已完成不等于可以递交；PS 保存记录、软件字段、画面疑点或“未检出”均不直接等同内容造假/真实，也不自动构成否决。

痕迹结案须确认每个范围内输入均有解析或登记状态、摘要和明细链接有效、失败及未支持项已列入未查范围、T/C/P 映射可回指。主报告须填写痕迹应检输入SHA-256集合，校验器要求其等于机器摘要输入集合且属于主报告登记输入；handoff 使用固定状态、路径和完整哈希字段。运行 `scripts/check_report_completeness.py` 验证实际产物与完成声明。图片另须确认视觉初筛 X / 应初筛 N 个图片对象中 X=N，未初筛清单为空或仅含已计数的装饰类排除项；元数据读取数、接触表生成数和视觉初筛数不得混报。本应检查而未检查的不是“盲区”，盲区仅限外部不可得、材料不可读或方法不支持。
