# 标书spec

输出 `投标输出/<项目名>/标书初稿讨论.md`，复用清单、目录和当前对话。规格说明面向后续写作与检查，只记录会改变响应内容的设计，不复述整份招标要求，不另建投标管理台账。

默认综合已经讨论和确认的内容，不因模板重新访谈。未确认的讨论结论标为“草案”；缺失信息记入待决或【待补】，只有会导致范围错误、事实虚构或不可逆承诺时才集中询问。

## 1. 定位与复用

读取项目 `AGENTS.md`；缺少时使用 `招标项目建档`。定位招标文件及有效澄清、相关事实素材、本次全套或局部范围、输出目录，以及当前对话中的用户决定和候选方案。

检查 `工程量清单.md`、`标书目录.md` 的来源版本和确认状态；缺少或失效时在本次调用内使用 `标书目录整理`。目录已冻结且来源未变则直接复用。

清单待核或目录未冻结时允许设计不受影响章节，相关决策标“草案”，受影响章节写明阻塞依据；不要求所有章节等一个局部问题。全套正式冻结仍要求目录及其清单依据有效且已确认。

## 2. 综合目标、方案与角色

- 从投标交付视角写“问题与目标”：本次需要形成什么投标响应，解决哪些评审、履约或协作问题。
- 从使用者视角写“响应方案”：准备提交哪些正文、表格、证据和交付物，如何回应招标要求；不把尚未确认的建议写成既定方案。
- 按本次范围识别实际相关方，包括适用的评审或定标读者、建设与使用运维角色、项目实施与服务角色、联合体及写作交接角色。写清角色与项目的关系、职责和关注点；无关角色不机械补全。
- 为每个相关角色编写编号角色需求：`作为<角色>，我需要<响应、证据或交付>，以便<评审、履约或协作结果>`。覆盖本次范围内的实质需求、边界和关键异常，每条关联已有 REQ/BOQ 或决策编号；角色需求只说明响应目的，不另建要求基线，不把写作分工冒充招标义务。

## 3. 分章与响应决策

按本次目录范围逐章读取所需招标原文与素材，不一次加载全部材料。复用清单、评分点、来源覆盖和全量要求索引，按 REQ/BOQ ID 定位要求；补充原文中会改变设计但尚未进入基线的内容时，调用 `标书目录整理` 更新受影响基线，spec 不自行分配 REQ/BOQ，更新后再继续受影响章节设计。

- 固定格式为骨架，方案内容让评分点容易定位，但不强制一项一标题。
- 每章记录必须回应的 REQ/BOQ、正文内容安排、关联角色需求、事实素材和缺口。
- 决策可包括章节结构、证据组织、项目角色与职责、联合体接口、技术路线、服务承诺及关键边界；记录依据和状态，不写正文。
- 资质、业绩、人员、价格和承诺仅使用确认素材；缺口写【待补】。具体报价由用户提供。
- 联合体按招标规则核对成员要求，只设计己方范围，其他成员接口写【待补·其他成员】。
- 每完成一章保存设计和进度。续接先读当前有效决策、待办与输入版本，只回看相关原文。

## 4. 核对标准与范围外

写清后续成果的验收口径：以可定位的正文、表格、附件和交付物证据判断响应，标题、目录和写作计划不算满足。按本次范围确定需要核对的 REQ/BOQ、门槛、评分、报价、一致性、外部引用及人工递交事项；实际检查交由 `标书检查`，本技能不提前判定正文合格。

明确本次不纳入的分册、章节、商务或技术内容、外部核验和交付操作。范围外事项不写成招标不适用，也不计为后续写作缺口。

## 5. 确认与交接

向用户交付可审阅草稿，集中确认新增策略、范围和实际疑问，不要求逐字通读全部内容。冻结前核对本次范围内格式、门槛、评分、清单、独立技术/服务义务、交付验收、固定附件及递交要求均有计划落点或明确待补；相关角色及角色需求已覆盖本次响应目的，核对标准和范围外事项明确。内部策略未定的部分不能标为已冻结，外部事实缺口可以保留待补。

变更使用新编号并注明“替代 D几”，将旧决策移到变更记录并标失效，当前有效区只保留执行依据。同名来源内容改变时先核对影响，不能仅靠文件名复用；目录需调整时先更新受影响目录版本，再冻结关联决策。

需要分批或多人交接时使用 `标书任务拆分`；一次性撰写全套或指定部分可直接使用 `标书撰写`。本技能不强制任务拆分。
