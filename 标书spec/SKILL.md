# 标书spec

产出 `投标输出/<项目名>/标书初稿讨论.md`。它是标书设计纲要：冻结内容边界、写作决策及其招标依据和计划落点；不写正文，不建立投标管理台账。

## 1. 摄入招标材料

向用户取得招标文件路径；若项目尚未建档，先使用 `招标项目建档`。

- 先判断文本是否可读。文本为空或乱码时按扫描件处理，逐页视觉识读；金额、分值、日期、资质条件等关键数字必须记录页码并列为人工核对项。
- 以实际招标文件为准识别工程、货物或服务类型，不套用固定蓝本。
- 抽取四类设计输入：
  1. 须知前附表中的项目参数和响应边界；
  2. 评标办法中的门槛条款、评分基准和所需佐证；
  3. 投标文件格式章节规定的初稿骨架；
  4. 技术标准、招标范围及必要工程量中会改变章节设计或方案内容的约束。
- 招标文件接受联合体时，补充抽取成员数量、牵头人、责任、资质与业绩认定规则，并把招标范围拆成可选择的分工块。
- 每项结论保留来源锚点：文件、页码，以及能取得时的章节或条款号。

主动形成疑问清单：门槛风险、评分素材缺口、歧义条款、联合体认定、关键数字异常和识读低置信处。能从原文或用户素材查明的事实自行查明；只有决策交给用户。

完成标准：四类设计输入均已覆盖；每个门槛、评分项和关键技术约束都有来源锚点；疑问清单只含真实未决项。

## 2. 确认目的地

按 `grilling` 方式一次询问当前可决定的全部事项，每问给出选项和推荐答案，允许用户“全部按推荐”。至少确认：

1. 独立投标或联合体投标；联合体必须确认己方承担范围。
2. 产出范围：全套初稿或指定部分。
3. 输出目录名，默认 `投标输出/<项目名>/`。
4. 资质、业绩、人员等投标人事实的素材路径。

创建：

```markdown
# <项目名> 标书初稿讨论

## 目的地
<产出范围与验收标准>

## 已决事项
- **D1**：<结论>
  - 依据：<文件/页码/条款>
  - 对应评分点/门槛：<有则填写；无则写“无”>
  - 计划落点：<影响内容或章节结构时填写；否则写“无”>

## 待决问题
- <问题>（卡在：<缺少的素材或人工决定>）
```

完成标准：目的地、投标主体、范围、素材来源和输出目录均已确认，spec文档已建立。

## 3. 逐节冻结设计

按招标文件规定的投标文件章节顺序推进：

- 强制格式是骨架；方案类内容在骨架内优先采用评分镜像，使每个评分点都有容易找到的响应位置，而不是强制“一项一标题”。
- 每节先列出本节门槛、评分点、技术约束和素材缺口，再询问需要用户决定的内容策略。
- 影响内容或章节结构的决策块必须填写“对应评分点/门槛”和“计划落点”；流程性决策写“无”。
- 投标人事实只采用用户确认的素材；缺口标为【待补】并进入待决问题。
- 联合体场景按成员核对门槛，只设计己方承担内容；其他成员接口标为【待补·其他成员】。
- 报价只讨论策略与依据，具体金额由用户提供。

完成标准：招标文件要求的每个章节都有设计结论；所有评分点、门槛和关键技术约束均能追溯到一个计划落点或明确待补项。

## 4. 冻结与交棒

向用户通读目的地、全部决策块、评分与门槛覆盖情况、计划落点和剩余待决问题。用户确认后冻结：后续变更追加新决策块，不改写旧结论。

提示用户使用 `标书撰写`，并提供直接撰写和拆分任务两种模式。

完成标准：用户明确确认冻结；剩余待决问题全部依赖外部素材或人工决定。
