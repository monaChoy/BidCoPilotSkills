# 检查方法与报告

## 方法选择与局限

| 方法 | 适用操作 | 判断边界 |
| --- | --- | --- |
| EXIF、XMP、软件字段 | 保留字段名、原值与提取工具；发现操作历史时逐条核对 | 字段可改写、继承或丢失；时间字段不是可信操作日志 |
| C2PA 等来源凭证 | 有验证工具时检查内容绑定、签名、信任状态和生成或编辑声明 | 发现字段与验证通过分别表述；有效凭证不保证现实内容真实，缺失不排除 AI |
| 局部放大 | 对照整图和相邻同类区域，记录像素坐标与原图尺寸 | 放大不增加原图信息；锐化产生的边缘不作源图证据 |
| ELA、压缩与噪声比较 | JPEG 等适用图像中辅助定位差异，保留重压缩参数和区域选择 | 纹理、扫描去底、压缩与多次保存可造成差异；不设通用判假阈值，不用于确认 AI |
| 原件与历史版本比对 | 区分逐像素相同、视觉相近与文字内容一致；必要时先对齐 | 图像变化与内容变化分别解释，扫描批次不同可影响像素 |
| AI 检测器 | 获授权后，对同一文件记录工具、版本、时间、标签和原始分数 | 分数不是通用真实性概率；未支持的模型和转存可能影响结果 |

对于一块背景或墨色异常，同时考虑局部拼接、扫描增强、去底和压缩等解释。以能区分这些解释的原件、较早版本或处理记录作为下一步核验材料。

PDF 任务先按 [PDF 证据提取与覆盖核验](pdf-evidence.md) 验证来源。原始对象流、解码像素、重编码副本分别登记；未核验原始流时，不用副本字段缺失作原文件的阴性结论。

## 分层与批量分析

- **编码层**：登记所有量化表及各分量对应的表号与采样参数，不能只看最后一个 DQT 段；一个段也可包含多张表。相同默认参数可能由多个软件产生，不据此确认具体编码器、统一重编码或原图历史已全部消失。Huffman 表未提取时明确标注。
- **元数据层**：APP1 可有 EXIF、普通 XMP 和扩展 XMP；APP13 可包含 Photoshop 资源。识别标准头再解析资源；发现 APP13 不能直接等同实际使用 Photoshop。IFD1 缩略图与主图明显不一致可作线索，相似不能排除小范围修改或同步更新。
- **像素层**：原分辨率测量，明确灰阶转换、坐标与阈值；报告暗像素数、中间灰像素数和分母。零分母记为不可计算，小分母不作稳定排序依据。浅色背景、二值化、重采样和压缩均会影响指标，不硬编码某案例的比例为通用判假阈值。
- **结构层**：优先使用 PDF/DOCX 解析能力检查引用与流，区分元数据、可见文字、图片与 OCR 层。当前文件无可见增量修订不代表历史上未经修改，完整重写可能不保留早期修订。

全量统计先按扫描件、现场照片、软件截图等类型分组，考虑分辨率、颜色和扫描方式。每张唯一源图只参与一次分布统计，保留重复引用关系，避免复用图片扭曲分位数。组内异常用于生成候选；候选再作局部与整页人工复核，记录被排除的误报原因。

感知哈希记录算法、位数、距离阈值和近空白判据；阈值按样本复核，不照搬固定数值。排除的近空白图仍在清单中，不作为已判真实。候选相似对先对齐，区分同模板不同内容与同源图改动；未经对齐的缩放差分不能证明内容被修改。

## 元数据脚本

从技能目录运行，需要 Python 3.11 或以上及提供 `ExifTags.IFD` 的 Pillow；先检查已有环境，不自动安装：

```bash
python scripts/image_metadata.py source/image.jpg source/image.png > metadata.json
```

输出文件哈希、尺寸、帧数、模式、EXIF 和 Pillow 可读取的信息；JPEG 另含首个扫描之前的 APP/COM 原始段清单、所有已读取量化表及分量采样参数。二进制字段以十六进制保存，EXIF 有理数保存为分子与分母。逐文件记录失败；任一失败时进程返回非零，成功项仍输出。脚本只接收明确的文件路径，批量清单由执行者从已登记图片生成。

段清单复用 Pillow 的头部读取结果，不是独立的完整 JPEG 扫描器。Photoshop 资源内部、扩展 XMP 重组、IFD1 缩略图、Huffman 表、PNG 块清单及 C2PA 验证未覆盖，输出中明确标注；已识别但未解码不写成“没有”。按需用已有专用工具交叉验证，依赖缺失先说明并取得安装同意，不移植未经验证的手写格式解析器。脚本不读取 PDF/DOCX，也不计算像素去重。元数据可能包含位置或身份信息，输出仅放本次工作目录。

## 原分辨率区域统计脚本

```bash
python scripts/region_stats.py source/image.png --box 10 20 110 220 --box 120 20 220 220 > regions.json
```

脚本同样使用 Python 3.11 或以上与已有 Pillow，不新增 NumPy 依赖。不传 `--box` 时统计整图；传入多个矩形时分别输出。坐标以存储像素为准，原点为左上角，右边、下边不包含；不应用 EXIF 旋转、不缩放。脚本输出原图尺寸与方向字段，证据图使用相同坐标基准。

输出 256 档灰阶直方图、唯一灰阶值、均值、标准差、暗像素与中间灰计数及比值、背景比例、RGB 最大最小通道差直方图及彩色像素数。暗像素默认灰阶小于 100，中间灰默认 100 到 205，背景默认大于 200 且小于 255，彩色默认 RGB 通道差大于 0；这些均为测量参数，不是判假阈值，可通过对应命令行参数调整。通道差不是 HSV 饱和度。暗像素为零时比值输出 null 和状态，不用极小数替代。

只接受单帧常见 8 位模式或二值图，拒绝高位深、浮点和含透明像素的输入；须先明确转换或背景方案。灰阶由 Pillow RGB 转 L，不执行 ICC 色彩转换，CMYK 也仅作库内转换；色彩判断有争议时另用正确色彩管理。二值图本身也可是真实扫描结果，纯白区域不证明拼接。脚本不自动寻找矩形边界、不估计倾斜、不做 dHash 聚类、不自动判断 PS 或 AI。

## Markdown 报告结构

1. 总体发现、来源与范围：输入版本、实际检查数量、唯一源图数量、排除项、失败项和未完成项。
2. 图片清单：编号、源文件及位置、对象与滤镜、来源类型、原始流与导出物哈希、保真核验、重复引用；原图元数据、缩略图初查、原尺寸局部复核、整页复核分别记录状态和证据路径，不用一个“已检查”合并。
3. 逐项发现：原图与局部图、尺寸及坐标、字段原值或观察结果、方法和参数、同类对照、局部及整页复核结果、解释、其他可能成因、结论边界；按编码、元数据、像素、结构标注覆盖与未覆盖项。
4. 第三方报告复核：原标签、对应原图、可复核依据、无法确认的机制；没有第三方报告时省略。
5. 核验与处理建议：需要哪份原件或历史版本、核对哪些内容，以及可纠正的来源或使用问题。

不把“未发现线索”写成“确认无 PS / 无 AI”，不把“发现异常”写成“确认造假”。

摘要分别给出已登记唯一源图数、原始元数据已检查数、仅缩略图初查数、原尺寸关键区域及整页复核数，以及失败、未支持、尚未深入检查的范围。各阶段可能重叠，不直接相加。登记和提取完成不等于鉴定完成；未知或部分覆盖时避免“全文件无异常”“全部图片深入检查完成”等表述。

## 虚构场景验收

| 输入 | 应有行为 |
| --- | --- |
| 软件字段为 Photoshop，但画面无明确异常 | 报告软件记录，具体操作未知；不认定改字或换章 |
| PNG 副本无 EXIF，但文件内嵌 JPEG 有软件字段 | 以各自文件为对象记录差异，不用副本缺失推翻原图记录 |
| 同一图片在多个位置重复引用 | 保留全部位置，按唯一源图分析，不累计为多次修改 |
| 落款背景与正文不同，没有纸质原件 | 定位异常并保留去底、拼接等解释，要求原件核对 |
| 画面有 AI 感，无凭证与检测器结果 | 给出具体视觉疑点，AI 来源仍不确定 |
| 来源凭证报告生成操作，但签名未验证 | 明确记录声明与验证状态，不写“已验证 AI 来源” |
| 某张图片提取或 EXIF 读取失败 | 单列失败原因，不计入已通过检查 |
| 编码参数相同，但来源不同 | 只报告参数一致，不断言同一软件或统一重编码 |
| JPEG 含标准头 APP13 或多个 XMP 段 | 登记全部可读段与覆盖状态，不把未解码当作不存在 |
| 缩略图相似、正文纯白但落款有灰阶 | 不排除后改，不直接认定拼接，列出可区分成因的原件要求 |
| 灰阶统计区域全白 | 暗像素为零，比值不可计算，不制造极大值参与排名 |
| 原图缩小后灰阶比变化 | 保留原分辨率测量结果，缩略图仅作展示 |
| 同图多次引用、近空白图大量重复 | 统计按唯一源图，同类分组；近空白不参与感知哈希候选匹配 |
| PDF 导出副本无 Software，但已知原始 JPEG 流有字段 | 原始流读出字段，副本标注转换来源，不据副本缺失作阴性结论 |
| 提取器遇到 Flate、复合滤镜或损坏 JPEG | 清单保留对象、位置及未支持或失败原因，不计为检查通过 |
| 只有缩略图初查，尚未检查关键文字、签章原图 | 摘要说明仅初查，原尺寸与整页复核状态未完成 |
| 提取脚本自检失败，或更换库版本尚未验证 | 停止原始流保真声明，先核验方法，不自动换用转换导出 |

## 方法依据

- [C2PA 官方解释](https://c2pa.org/specifications/specifications/2.2/explainer/Explainer.html)：来源凭证与真实性的区别。
- [NIST 合成内容技术报告](https://www.nist.gov/publications/reducing-risks-posed-synthetic-content-overview-technical-approaches-digital-content)：检测、来源记录及其局限。
- [Pillow 文件格式文档](https://pillow.readthedocs.io/en/stable/handbook/image-file-formats.html)：元数据读写能力按实际版本核对。
