# 招标项目建档

为一个投标工作目录建立或刷新**档案**——一份 AGENTS.md，记录项目情况、招标文件、参考文件的确认结论。核心纪律：**先摸底、后落档**——文件分类先给用户过目确认，确认结论才写进 AGENTS.md。

## 1. 摸底

- 确认项目目录：默认当前工作目录；用户给了路径则用该路径。
- 检查 AGENTS.md 是否存在：存在 → 走**更新分支**，先读它，记下已确认的招标文件与参考文件清单；不存在 → 走**新建分支**。
- 盘点文件：`rg --files`（无 .git 的目录改用 `find . -type f`），`file` 核实真实格式。
- 识别**招标文件候选**：文件名含 招标文件/招标公告/资格预审/竞争性谈判/磋商/比选，或正文含 投标人须知前附表/评标办法/投标文件格式。PDF 先试提取文本，提取为空即扫描件——标注【扫描件】，凭文件名和版式初判，正文待用户确认。
- 其余文件按用途初分为**参考文件**（初设方案、项目简介、图纸、预案、成果手册等）；归不了类的列为【待判断】。

完成标准：每个文件都有初步分类（招标文件候选 / 参考文件 / 待判断），扫描件均已标注。

## 2. 汇总询问

向用户汇报并逐项确认：

1. **招标文件**：是否存在、是哪个文件。多个候选逐一列出，用户拍板；一个都没有时明确告知并询问是否稍后放入。
2. **参考文件**：逐个列出初步分类与判断依据（一句话），用户增删改。
3. **项目情况**：项目名、招标人/业主、项目类型、当前阶段（公告期 / 编制中 / 已截标……）。能从文件里读到的先给出草稿让用户改，读不到的直接问。

更新分支只汇报与已有档案的**差异**：新增文件、消失的文件、分类变动；无变化的部分不重问。

完成标准：三项均有用户确认结论，更新分支的差异已全部澄清。

## 3. 落档

- 新建分支：按 [AGENTS模板.md](AGENTS模板.md) 创建 AGENTS.md，填入确认结论。
- 更新分支：只改确认结论有变化的小节，其余内容原样保留。
- 创建或更新 AGENTS.md 时必须以 UTF-8 编码写入，不得使用 GBK、GB2312 或系统默认编码；写入后用 `file --mime-encoding AGENTS.md` 核对编码为 `utf-8`。
- 已有的其他约定（输出目录、术语口径、工作流程）原样保留，建档只覆盖模板中的三个小节。

完成标准：AGENTS.md 存在、编码为 UTF-8，且内容与用户确认结论一致；向用户复述落档结果。
