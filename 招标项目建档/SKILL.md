# 招标项目建档

产出或更新项目 `AGENTS.md`。先把来源盘点清楚、和用户确认，再写入档案；不要把生成的文件登记为参考资料。

## 1. 盘点差异

默认在当前项目目录操作；用户给了路径，就用用户的路径。先读已有档案，用 `rg --files` 盘点输入文件，必要时用 `find` 找出不可见的文件，用 `file` 核实真实格式。排除版本控制目录、缓存和生成输出；如果用户明确指定某份投标输入放在了输出目录里，仍交给本次撰写或检查去记录，不要一概忽略。

识别哪些是招标文件、有效澄清、参考资料和投标人事实材料；扫描件只需标注，建档时不对全文做 OCR。分不了类的列入"待判断"。每个来源都记录路径、版本/日期、大小和修改时间；文件名没变但内容变了的，也要核对影响，不能只查文件的增删。

只有招标来源、澄清或已确认事实材料出现新增、删除、替换、分类或效力变化时，才更新档案。自动生成的章节、任务、README 和报告由各技能自己维护，不重新走建档流程；没有实质变化就直接复用原档案。

## 2. 确认来源

先从文件里提取项目名、招标人、项目类型和当前阶段，交给用户核对。新项目集中展示来源分类，已有项目集中展示实质差异；用户已经明确指定并确认过的材料，不重复询问。说不清哪份澄清有效、候选招标文件和转换版对不上号时，把具体疑问指出来，不要猜。

明确正文读取文件和原始版式文件的对应关系，项目已有约定的从约定；参考文件不能替代招标依据，事实材料要和背景资料分开登记。

## 3. 保存

按 [AGENTS模板.md](AGENTS模板.md) 创建或更新对应小节，保留用户在档案里的其他约定。用 UTF-8 写入，禁止 GBK/GB2312 和系统默认编码；写完后用 `file --mime-encoding AGENTS.md` 验证为 `utf-8`。

交付时给出确认后的差异清单和路径。后续技能只核对来源是否有变化，不要求用户重新确认没变过的信息。
