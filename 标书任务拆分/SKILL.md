# 标书任务拆分

输出 `投标输出/<项目名>/写作任务清单.md`。不建立外部议题或额外管理台账。

## 1. 核对依据

读取项目 `AGENTS.md`、当前招标及澄清、目录、spec和已有任务清单。缺少项目档案先建档；缺少可执行设计时使用 `标书spec` 补充本次范围设计。

只有依据已确认且不受待核影响的章节安排为可执行任务；其余明确阻塞原因，不强迫无关章节等待整个spec冻结。核对来源版本及当前有效决策，不执行已被替代的旧结论。

## 2. 拆分

- 默认一个任务交付一个可独立验收的章节文件；不把每个清单行、小标题或评分点机械拆成任务。
- 每个计划落点只设一个主任务，其他任务引用其结果；仅当确实需要前一任务正文才能完成时设置依赖，共读招标文件不构成依赖。
- 缺事实可用【待补】继续，缺内容边界决定则阻塞相关任务。
- 已有清单保留稳定编号和有效状态。要求变更使已完成任务失效时保留旧成果，将任务标“需更新”并写明原因，不能因为曾完成就保留完成状态。

使用以下结构，先形成可审阅草稿：

```markdown
# <项目名> 写作任务清单
- 范围：全套 / 局部（明确章节）
- 当前版本及确认情况：

## 共同输入
<项目档案、招标、澄清、目录及spec的路径、版本/日期、大小、修改时间>

## 写作任务
### W-001 <标题>
- 范围及依据：<章节、当前决策编号、招标条款/页码>
- 所需素材：<路径及相关位置；缺口>
- 依赖：<真正必要的任务；无则无>
- 输出：<章节文件>
- 完成条件：<正文响应、证据或允许的待补登记>
- 状态：未开始 / 进行中 / 阻塞 / 已完成 / 需更新
- 下一步或阻塞原因：
```

## 3. 交接与更新

只对不明确的粒度、依赖或范围集中询问；用户已明确要求按章拆分时可直接完成，不再索要形式确认。交付前检查无重复主任务、依赖无循环、素材和输出可定位。

续接从任务文件及来源版本恢复，读取选中任务及其依赖，不要求重读全部历史对话。使用 `标书撰写` 执行；全套或局部范围标识保留，局部任务全部完成不得触发全套检查。
