# 标书总控

本技能是标书技能包的**编排入口**：只做阶段判断、选型推荐和下一步交接，不重复实现各子技能的写作、检查或评分细则。用户说不清该用哪个技能、或需要整条链路怎么走时，优先用本技能。

## 1. 快速定位当前阶段

读取用户意图与项目目录（默认当前项目；用户给了路径则用该路径）。有 `AGENTS.md` 或 `投标输出/<项目名>/` 时先扫现有产物，**并读产物头部状态字段**（草稿/冻结、章节状态、报告「未完成」等），再对照路由表；没有档案时默认从建档开始。用户意图已明确指向某一子技能时，直接推荐或调用该技能，不多一轮「请确认是否调用」。

| 阶段信号 | 当前大致位置 | 通常下一步 |
| --- | --- | --- |
| 无 `AGENTS.md`，或招标/澄清/事实材料刚变 | 未建档或档案失效 | `招标项目建档` |
| 已有档案，缺有效清单/目录，或目录标「草稿/未冻结」且要做响应映射 | 材料已确认、骨架未就绪 | `标书目录整理` |
| 要定策略、章节设计、内容边界 | 目录可用或可补齐 | `标书spec` |
| 要分批/多人写、要任务清单 | 设计已可执行 | `标书任务拆分` |
| 要写/续写/补章节正文；或 `撰写进度.md` 有「阻塞」待补材料/决定 | 范围已明确（可无目录/spec） | `标书撰写`（阻塞时先补材料或做决定） |
| 要审标、合规、废标风险、整改复核；或最新检查报告状态为「未完成」 | 有投标稿（建档已完成） | `标书检查`（未完成则续查） |
| 要结构核对、正文评分检查或明确要求估分 | 有评分办法可依 | `标书评分` |
| 只问「从哪开始 / 下一步」 | 任意 | 本技能给出路由后停，或经用户确认后调用推荐技能 |

一次只推荐**一个**主入口（可附带可选前置）；用户意图冲突时集中问一次，不代选。

## 2. 路由表（按需求选型）

| 用户需求 | 推荐流程 | 说明 |
| --- | --- | --- |
| 不知道从哪开始 / 要整条链路 | 先本技能定位 → 再按下列行走 | 不要求本技能包全部技能都跑 |
| 已有标书，要审核 | 建档 → 检查 | 无档案先建档；检查可直达，目录/spec 非必须 |
| 直接起草 | 建档 → 撰写 →（全套完成后）检查 | 目录/spec/任务清单均可跳过 |
| 先设计再写 | 建档 → 目录 → spec → 撰写 → 检查 | 设计后可加任务拆分 |
| 分批或多人交接 | … → spec → 任务拆分 → 撰写 | 局部任务完成 ≠ 全套完成 |
| 核对评分或估分 | 建档 → 评分 | 估分须用户明确要求 |
| 只查规范引用或前后矛盾 | 建档 → 检查（限定单项范围） | 由 `标书检查` 按单项执行；单项结果不代表全套已检查 |

交付给用户时用简短列表复述：当前阶段、推荐技能名、为何选它、可选前置、明确不做的事。

## 3. 交接规则（编排边界）

- **只编排，不替代**：建档确认、清单提取、策略设计、任务拆分、正文撰写、只读检查、评分细则一律交给对应子技能；本技能不产出章节正文、检查报告或评分表。
- **共同边界**：不编造投标人事实；不擅自报价或代填金额；不做 Word/PDF 排版、签章、密封、CA、平台上传与递交操作。
- **产物落点**：运行产物在投标项目的 `投标输出/<项目名>/`（章节在 `正文/`，进度清单为 `撰写进度.md`）；本仓库只维护技能定义。
- **调用方式**：意图明确或用户确认推荐后，直接调用对应子技能（或告知用户触发该技能的说法）；撰写后检查须由独立检查上下文执行，本技能不代替检查独立性要求。派检查前须已由主上下文收齐「检查模式 + 是否模拟评分」（见 `标书撰写`）。

## 4. 与本技能包子技能关系

```text
标书总控（入口/选型）
    │
    ├─ 招标项目建档     → AGENTS.md
    ├─ 标书目录整理     → 工程量清单.md、标书目录.md
    ├─ 标书spec         → 标书初稿讨论.md
    ├─ 标书任务拆分     → 写作任务清单.md
    ├─ 标书撰写         → 正文/*.md + 撰写进度.md
    ├─ 标书检查         → 标书检查报告-*.md（只读）
    └─ 标书评分         → 标书评分报告-*.md；结构/正文核对；明确要求时才估分
```

前置关系以各技能正文为准：多数路径需要先有有效建档；检查与评分不强制目录/spec；撰写可不经设计直接起草。本技能只做导航，不修改上述契约。
